# EventSpace 设计系统规范 v1（待视觉稿复核）

> 范围：页面视觉、排版、组件形状与性能边界。它不定义业务逻辑；在高保真稿复核前，不进入功能代码实现。

## 1. 设计原则

1. **活动感而非 SaaS 感**：每个房间是短暂活动的容器，首页和归档应像回忆册，而不是数据后台。
2. **高级但不厚重**：暖白、墨黑、低饱和灰阶、强留白、杂志式标题；不引入品牌彩色系统。
3. **信息永远先于装饰**：卡片、阴影和动态用于建立层级与反馈，不能遮挡内容或拖慢操作。
4. **移动优先、桌面扩展**：移动端保持单一阅读重心；桌面端只增加空间与辅助栏，不复制复杂后台布局。
5. **性能是视觉质量的一部分**：禁止渐变、毛玻璃/高斯模糊、纹理、大面积滤镜和会持续触发重排的动效。

## 2. 字体与加载预算

| 角色 | 方案 | 使用范围 |
| --- | --- | --- |
| 界面无衬线 | Geist Variable（Latin 子集） | 正文、表单、聊天、时间、按钮、信息密集界面。 |
| 展示衬线 | Bodoni Moda Variable（Latin 子集；仅必要字重） | 公开首页主标题、归档回忆册标题、少量大标题与 EventSpace 字标。 |
| 回退 | `ui-sans-serif, system-ui, sans-serif` / `Georgia, serif` | 字体未到达时立即显示，保证首屏不等待。 |

- 两套字体均使用 Next.js 字体优化并从本站静态资源提供；浏览器不在运行时请求 Google 等第三方字体域名。
- 展示衬线不应用于聊天、表单、行程、投票和成员列表。
- 发布前检查字体传输体积；展示字体仅保留 Latin 子集与设计实际使用的字重。若达不到首屏性能预算，先缩减展示字重，再考虑更换字体，不牺牲聊天和回忆录性能。

## 4. 尺度、形状与阴影

| 项目 | 规范 |
| --- | --- |
| 间距基线 | 4px；常用间距为 8、12、16、24、32、48、64px。 |
| 大卡片圆角 | 24px。 |
| 次级卡片/底部面板 | 20px。 |
| 输入、标签、小工具 | 14–16px。 |
| 主按钮 | 18px；移动端最小高度 48px。 |
| 内容最大宽度 | 常规页面 1240px；阅读/认证页 560px；房间聊天主列 760px。 |
| 卡片边框 | 1px `line`，仅在阴影不足以分层时使用。 |
| 阴影 | 静态、低透明度、多层柔影；悬浮或按下只调整强度和 1–2px 位移，不动画模糊半径。 |

## 5. 排版层级

| 层级 | 字体 | 建议尺寸与行高 | 场景 |
| --- | --- | --- | --- |
| Display | Bodoni Moda | 移动 48/0.98，桌面 80/0.94 | 首页情绪化标题。 |
| H1 | Bodoni Moda | 36/1.05 | 归档回忆册、少量页面标题。 |
| H2 | Geist 600 | 24/1.2 | 区块标题、房间标题。 |
| Body | Geist 400 | 16/1.55 | 正文、消息。 |
| Small | Geist 500 | 13/1.35 | 时间、状态、说明。 |
| Label | Geist 600 | 12/1.2，适度字距 | 导航与小标签。 |

- `EventSpace` 字标使用 Bodoni Moda 的较重字重与紧凑字距，第一版不设计独立 Logo 图形。

## 6. 动效 token 与性能边界

| 类型 | 时长 | 曲线 | 用途 |
| --- | --- | --- | --- |
| 点击/按压 | 120–160ms | 轻快 ease-out | 按钮、图标、卡片按下。 |
| 面板/抽屉 | 220–280ms | 轻弹性 cubic-bezier | 底部分享卡、评论区、更多菜单。 |
| 页面/标签切换 | 180–220ms | 克制 ease-out | Chat、Photos、Itinerary。 |
| 首屏入场 | 360–520ms | 分时缓出 | 抽象照片与 UI 卡片轻微上移后定格。 |
| 主题切换 | 200ms | linear/ease | 仅颜色，不让内容重入场。 |

- 只动画 `transform` 与 `opacity`；滚动、拖动、缩放中的元素不执行阴影、滤镜或布局动画。
- 120Hz 设备以接近 120fps 为目标；普通设备优先稳定输入、滚动和拖动。
- 当前 Photos 使用 CSS Grid 与详情层；若未来重启 Book，应以 DOM/CSS transform 为主且不引入重量级 WebGL 渲染器。

## 7. 页面骨架

### 公开首页

全视口首屏：真实活动照片与克制 UI 片段作背景，前景为情绪化标题、`Create a room` 主按钮、`Join with a link` 次按钮。右上角仅保留登录和低调菜单。首屏下方以三张精致卡片介绍 Chat、Photos、Itinerary。

### 用户首页

公开 Landing 只属于未登录入口，不进入登录后的导航层级。登录后的 Rooms 首屏直接从“进行中 / 已归档”切换与房间卡片开始，不显示营销式欢迎标题。默认进行中；移动端以单张大卡片横滑展示，照片牌堆预览约占主视觉，信息置于底部。搜索、收藏和筛选不改变横滑阅读结构；另提供双列纵向浏览。Grid 偏好和最近阅读卡片只在当前标签页恢复；双列牌堆最多显示五张，不能裁剪房间照片数据。

### 房间内

房间使用单层悬浮顶部胶囊：左、右两侧为相邻页面的动态图标，中间严格居中显示房间名与状态/倒计时，并作为 Room options 入口。Chat / Photos / Itinerary 三页同时挂载在浏览器原生横向滚动轨道并强制吸附；非交互内容区横拖翻页、各页内部纵拖滚动，侧边按钮可直接切页。初始定位 Photos。页面弹层渲染到视口级，不受横向轨道坐标影响。聊天使用彩色消息卡与固定悬浮输入栏，Photos 使用紧凑照片网格和详情层，行程采用按日期分隔的纵向时间卡。

### 归档

以活动照片和活动信息作为归档入口，再进入 Chat、Photos、Itinerary。用户可为自己的归档列表挑选照片封面。

## 2026-07-26 当前同步：聊天卡片与悬浮输入栏

- 普通消息是完整卡片而非内容宽度气泡：成员标识、姓名、时间、正文处于同一张大圆角色块；卡片颜色按消息稳定随机分配，亮暗主题通过语义色混合保持对比。
- 本人消息不使用固定深色：仍使用随机色，仅将卡片缩至约三分之二到四分之三宽、成员标识放至右侧。
- 相邻消息卡以轻微垂直重叠形成连续堆叠；不在卡片上显示未读数字圆点。系统消息仍是独立弱文本。
- 输入栏是单层白色悬浮胶囊，左侧为工具入口、右侧为黑色主操作。空草稿保持按住录音，存在文字时弹性切换为发送；禁止再套第二层有边框的输入框。
- 卡片进入、按压和主按钮切换使用 iOS 式弹簧曲线；`prefers-reduced-motion` 下移除非必要动画。

## 8. 已确认的非视觉边界

- 当前 Phase 0 不将无障碍设计设为页面视觉约束；此项在核心主体验稳定后再独立评估。
- 真实地图缩略图不纳入第一版，行程只提供地点文字和 Google Maps / Apple Maps 外链。
- 付费入口不常驻；只在创建时选择或超配额时呈现。
- PWA 首访显示一次轻量安装提示；浏览器是否给出原生安装请求取决于平台。
## 2026-07-18 历史同步：旧设计系统落地补充

> 本节中的 Board 组件规则保留为历史记录；当前回忆录规则见 2026-07-23 章节。

当前实现继续保持低饱和、克制、移动端优先的方向，但以下组件规则已经在正式 mock 中形成，应作为后续实现参考：

- 字体：生产构建使用 `public/fonts` + `@font-face`，保留 Geist 正文字体和 Bodoni Moda 衬线标题，不再依赖 `next/font` 远程下载。
- Rooms 筛选：当前状态按钮 + 下拉其他选项；Edit 为文字+图标式按钮，编辑态才显示收藏/删除。
- Rooms 控制条：筛选、搜索、单键视图切换与 Edit 共享同一纯色工具条；搜索和编辑通过内容转换表达模式，不叠加新的悬浮输入卡或多组胶囊。
- Rooms 横滑：当前卡保持完整尺寸，相邻卡只用轻微 `transform` / `opacity` 退后；底部进度块连续跟随滚动，吸附完成后更新序号。
- Rooms Grid 牌堆：静止和拖动均最多露出五张照片；进入/离开预备层的收尾 transform 必须与最外层静止 transform 一致，避免切换数据窗口时产生跳帧。
- 投票创建：卡片内部为纯色背景，卡片外覆盖层为暗色半透明；按钮、时间、匿名开关都在卡片内部完成。
- 投票展示：选项投票后变成进度条，百分比在选项内部，人数保留在右侧。
- Chat 输入：输入框是固定底部功能条，不随消息数量漂移；语音按钮属于输入框内部控件。
- Board 工具：常驻区收敛为 fit、背景、添加三键 Dock；Camera / Photos / Note / Doodle 放入纯色卡片式创建托盘。
- Board 内容：照片按真实比例，文本标注尺寸随内容和用户调整变化。
- Board 照片详情：使用全视口暗色层和单一内容表面，大图保持相框与原比例，作者、纵向评论和底部输入形成连续阅读层级；不使用弹幕或嵌套卡片。
- Board 相框：照片上传后使用单层横滑卡选择 Pin / Gallery / Instant / Tape / Dark；居中卡即时成为当前选择，不再要求二次点击激活。
- Board 背景：Stone / Linen / Night 为克制基础材质，Herbarium / Clover / Bluebell 使用低饱和本地植物纹理；Board 与 Rooms snapshot 必须消费同一背景值。
- 涂鸦板：全屏，不使用弹窗标题；工具悬浮底部，brush 预览只在调整画笔时出现。
- 覆盖层：Poll History、文本预览、评论输入等使用暗色半透明背景建立层级，但内容卡片本体保持纯色和清晰边界。
- Account：不使用营销 Hero 或设置表单集合；以单列纯色身份/状态卡和可视化主题选择器组织信息。顶部品牌必须几何居中，返回图标保留 44px 触控区但不强制显示圆形外框。
- Account 编辑：轻量资料修改在身份卡内原位展开；模式切换和本地数据清除使用全视口底部卡，进入与退出均使用 180–260ms 动效。

## 2026-07-19 历史同步：旧 Board 交互卡片与动效规则

- Chat 附件、消息操作使用从底部进入的卡片层；图片查看、媒体发送、Votes 和 Doodle 使用 Portal 覆盖整个视口，不能被 Room header/tabs 的层叠上下文截断。
- Board 画布是主视觉，常驻控件必须退后：三键深色 Dock + 单层纯色功能卡，不在画布上平铺六个同权按钮。
- Note 输入嵌在便签卡内部；非选中样式只作为相邻卡片提示，使用横向 scroll snap，不呈现传统字段列表。
- Doodle 纸张保持最大视觉面积；颜色、笔刷/橡皮/尺寸、撤销/重做、关闭/确认分成紧凑悬浮卡，390px 宽度下不得横向裁切。
- 动效统一使用 `transform` / `opacity`：Dock 入场、托盘缩放进入、选中边框、Studio 上移和 Sequence 内容入场；拖动与缩放期间不做布局动画。
- 所有 Board 动效遵循 `prefers-reduced-motion`；长按本人内容可使用极短振动反馈，但不能依赖振动表达唯一状态。

## 2026-07-23 历史同步：回忆录设计语言

- 旧 Board 工具、相框、图钉和无限画布规则停止扩展，仅保留为历史组件参考。
- Photos 中每个内容单元是现实书本的双页摊开：直角纸页、清晰中缝、克制纸面色与阴影；禁止把书页套入圆角卡片或外层装饰容器。
- 纸张样式使用低饱和 ivory / linen / sage / sky 纯色与极轻材质差异，亮暗主题都优先保证照片、正文与页码对比。
- 长按 spread 使用 180-280ms 的提升与全视口暗色遮罩，工具 Dock 紧贴书页下方；不保留旧 Board 的下沉或按压残影。
- Book 封面使用 Bodoni 展示字体、克制线框和书脊阴影；内页保持内容优先。封面首帧占位与 StPageFlip 完成态尺寸一致，初始化前不显示畸形书体。
- Single 视角接近占满移动端可用宽度，Spread 保留完整双页轮廓。视角平移和翻页使用不同节奏，只有翻页完成后才切换新页侧。
- Book 控制栏收敛为前一页、Single/Spread 分段、后一页；图标按钮提供可读名称，状态文字保持可辨识，并遵循 `prefers-reduced-motion`。
- 照片无相框和额外边框，保持原比例；文本透明背景。caption 只存在于照片详情评论层，不覆盖在书页照片上。
