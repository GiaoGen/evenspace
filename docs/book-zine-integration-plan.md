> 状态：产品主边界已确认，视觉方向与少量细节继续澄清；尚未进入开发  
> 建立日期：2026-08-02  
> 最近更新：2026-08-03  
> 当前版本：v0.2  
> 维护方式：本文件是持续更新的产品、设计、数据与技术决策基线。未关闭“开发前阻断项”之前，不开始功能实现。

## 1. 目标与当前共识

Book 功能用于把照片、照片下的评论以及可选行程信息整理为可翻阅的数字 zine。系统应协助用户形成封面、章节与有审美的版式，但最终阅读与渲染必须稳定、可重复、可重新生成。

已经提出两个入口：

1. **Room 内入口**：一房一本共享 zine。Room 结束后由 Host 创建；Host 选择风格，并通过“手动选图”或“AI 精选”决定参与排版的照片。系统带入这些照片下的评论与房间行程。
2. **Rooms 页 Book 入口**：使用现有 Create 菜单中的 Book 项创建独立 zine；它不依赖任何 Room，只允许用户重新手动上传照片。

用户不参与页面排版。生成后只开放三类控制：更换风格、请求 AI 整本重排、改选某张照片对应的评论摘录。自由拖拽、任意布局、逐页微调不属于产品方向。

首版作品仅私有在线阅读，不提供公开分享、PDF 或印刷。

阅读器指定采用 [Nodlik/StPageFlip](https://github.com/Nodlik/StPageFlip)，并需要多套视觉风格。

当前暂定产品语言：

- `Book`：产品入口或功能名称。
- `Zine`：一本实际生成、编辑和阅读的作品。
- 最终对外是否统一为 Book、Zine 或其他名称，仍待确认。

## 2. 初步结论

### 2.1 AI 辅助排版可行，但不应让 AI 直接生成 HTML/CSS

推荐采用“**AI 艺术指导 + 参数化模板渲染**”的混合模式：

- AI 负责看图、理解评论与行程、选封面、编章节、选择版式、决定照片组合、裁切焦点和文字层级。
- 服务器只接受符合预定义 JSON Schema 的布局计划。
- 前端用经过设计与测试的 HTML/CSS 版式原语渲染页面。
- StPageFlip 只负责翻页和阅读交互，不拥有业务数据，也不决定版式。

不建议首版让模型输出任意 HTML、CSS 或整页位图，原因是：

- 结果不可控，文字溢出、照片遮挡、移动端错位很难彻底验证。
- 很难保持同一风格在不同作品和重新打开后完全一致。
- 任意代码或样式输出增加安全风险。
- 位图页不利于清晰文字、无障碍、响应式阅读与后续 PDF/印刷。
- 每次微调都要重新生成，成本与等待时间都会放大。

模板也不应只是少量固定“照片格子”。更合适的是建立一套参数化版式语法：单图满版、跨页主视觉、双图对话、三图节奏、留白引语页、章节扉页、时间轴页等。AI 在受控语法内组合，并可调整有限参数，例如焦点、留白方向、字号级别、图文比例和色彩 token。这能在审美变化与工程稳定之间取得平衡。

### 2.2 多模态成本不是首要风险，反复生成和工程复杂度才是

当前房间生产限制是每个房间最多 25 张照片。按 OpenAI 官方视觉计费规则，`gpt-5.4-mini` 的图片输入以 32×32 patch 计费并乘以 1.62；其公开价格为输入 $0.75 / 1M tokens、输出 $4.50 / 1M tokens。以下只用于立项预算，接入时必须重新读取实时价格。

假设一次生成输入 25 张照片，模型只输出结构化布局 JSON：

| 方案 | 图片处理假设 | 估算输入 | 估算单次总模型成本 | 适用范围 |
| --- | --- | ---: | ---: | --- |
| 低成本首稿 | 每张缩放为 512×512，low detail | 约 10.4K 图片 tokens | 约 **$0.03 / 本** | 章节、封面候选、布局选择 |
| 高细节首稿 | 每张按高细节上限估算 | 约 62.2K 图片 tokens | 约 **$0.07 / 本** | 需要更精确裁切与细节判断 |
| 生成 + 2 次重排 | 同一作品最多三次完整调用 | 上述约 3 倍 | 约 **$0.09–$0.21 / 本** | 用户反复换风格或重排 |
| 渲染后视觉复核 | 额外把页面缩略图交给模型审稿 | 视页数和循环次数 | 通常再增加 **$0.02–$0.10 / 轮** | 后续高质量或付费模式 |

估算未包含税费、供应商价格变化、网络流量、队列计算、页面截图、Storage 和监控成本。文本评论和行程通常只占很小一部分输入成本。若不用图像生成模型创造新封面插画，则不存在高额图片输出费用。

建议首版成本策略：

- 普通生成使用 512px 派生缩略图和低成本视觉模型。
- 只有封面候选或模型判断不确定的照片才升级到高细节。
- 生成前先做确定性去重、尺寸检查和元数据整理。
- 每本最多 1 次初稿 + 2 次用户主动重排；之后提示成本或使用额度。
- 记录每个生成任务的模型、prompt 版本、输入/输出 token、估算美元成本、延迟和失败原因。
- 设置单任务硬预算与全局月度预算，超限时回退到确定性排版。
- 规模预算可暂按每 10,000 本约 $300–$700 的“一次首稿”模型成本估算；真实值必须用试运行样本校准。

官方参考：

- [OpenAI Images and vision：图片细节、缩放与 token 计算](https://developers.openai.com/api/docs/guides/images-vision)
- [OpenAI GPT-5.4 mini 发布与价格](https://openai.com/index/introducing-gpt-5-4-mini-and-nano/)
- [OpenAI 模型目录](https://developers.openai.com/api/docs/models)

### 2.3 StPageFlip 可以采用，但需要隔离适配层

StPageFlip 适合当前需求：MIT 许可、无运行时依赖、支持 HTML 页面、封面硬页、portrait/landscape、移动端和更新页面。`page-flip` 当前 npm 版本为 2.0.7。

需要接受以下风险：

- npm 包约五年没有发布新版本，维护活跃度低。
- 项目当前是 Next.js 16.2.10 + React 19.2.4，不能默认认为旧 React wrapper 与当前生命周期完全兼容。
- portrait 模式会 clone HTML 页面；书页内部不应放表单、重复 id 或复杂交互。
- resize、React 重渲染、快速切换作品和销毁重建需要专项验证。

因此计划直接在客户端适配核心 `page-flip`，不把 `react-pageflip` wrapper 作为默认依赖。适配层负责动态加载、初始化、`updateFromHtml`、当前页同步、resize 重建和 `destroy()`。书页保持只读；上一页、下一页、目录、模式切换等操作放在被 clone 的页面 DOM 之外。

阅读器必须是可替换的表现层。即使 StPageFlip 出现兼容问题，zine 的布局文档仍可被普通分页阅读器或未来 PDF renderer 使用。

参考：

- [StPageFlip README 与 API](https://github.com/Nodlik/StPageFlip)
- [page-flip npm 版本记录](https://www.npmjs.com/package/page-flip?activeTab=versions)

## 3. 当前仓库审计

### 3.1 已具备的基础

- Next.js 16.2.10、React 19.2.4、Supabase。
- 房间照片已进入 `public.photos`，照片评论已进入 `public.photo_comments`。
- 房间行程已进入 `public.itineraries`。
- 私有媒体使用 `room-media` bucket、RLS 和签名 URL。
- 图片已有 display、thumbnail、placeholder、尺寸和 revision 等派生信息。
- Room 页面已有 Photos、评论详情、Itinerary 和成员权限基础。
- `/rooms` 已有一个被禁用的 Book 菜单项，可作为入口位置候选，但是否等同于需求中的“右上角 Book 按钮”需要确认。

### 3.2 必须补齐的数据能力

1. **没有正式 zine 数据模型**：当前没有 zine、版本、章节、页面、布局、来源照片或生成任务表。
2. **没有拍摄时间**：`photos.created_at` 是上传时间，不是照片拍摄时间；当前图片压缩链路也没有持久化 EXIF 时间。若“按时间”是按真实拍摄时间编章，需要新增 `captured_at`、时区和缺失值策略。
3. **评论没有内容类型**：生产 `photo_comments` 只有正文与作者，无法区分正式 caption、精选引语和普通讨论。mock 层虽有 `caption` 兼容字段，但不能当作生产契约。
4. **全局手动 Book 没有上传边界**：现有上传 RPC 要求用户是某个 active room 的成员，不能直接用于独立 zine。
5. **当前房间照片上限为 25**：需确认 zine 是否沿用 25 张上限，手动入口是否允许更多照片。
6. **没有异步生成任务与用量台账**：需要状态机、幂等、重试、预算、超时和生成版本记录。
7. **没有快照语义**：照片、评论或行程在 zine 生成后发生修改或删除时，当前没有规则决定已生成作品如何变化。

### 3.3 历史实现的处理原则

仓库文档记录 2026-07-23 曾存在 Memoir/Book、双页、纸张样式和 `page-flip` 原型，但该实现已在 2026-07-26 后撤回，相关运行时代码和依赖当前都不存在。

本次原则：

- 不恢复旧 reducer 命令或旧 `boardItems` / `boardComments` 兼容模型。
- 可复用历史验证结论，例如客户端动态加载、阅读器生命周期分离、偶数页和封面尺寸稳定。
- 新功能直接基于生产 `photos`、`photo_comments`、`itineraries`、`assets` 和新的 zine 领域模型设计。

## 4. 推荐产品流程

### 4.1 Room 内入口

确认后的流程：

1. Room 结束，照片、评论与行程进入不可继续编辑的归档状态。
2. Host 在 Room 内点击 Book。
3. Host 选择选图方式：
   - **手动选图**：Host 直接勾选照片。
   - **AI 精选**：AI 按画面质量、时间覆盖、人物/场景多样性、评论价值与重复度给出建议集合；是否仍需要 Host 最终确认，见第 12 节剩余问题。
4. Host 选择两套风格中的一套。
5. 系统展示选中照片、AI 将使用的评论范围、预计页数与生成额度。
6. 后台冻结来源快照，按拍摄时间匹配行程并建立章节候选。
7. AI 完成封面、章节、评论摘录和整本布局，系统执行确定性校验与一次受限视觉复核。
8. Host 预览成品，只能：
   - 更换整本风格；
   - 请求 AI 整本重排；
   - 为某张照片改选另一条原始评论摘录。
9. Host 确认当前版本，一房一本的共享 zine 对 Room 成员私有可见。

手动选中的照片默认全部进入成品。AI 精选模式选择出的最终集合也全部进入成品。封面主图可以在内页再出现一次，其他照片默认不重复。

### 4.2 Rooms 页独立入口

确认后的流程：

1. 用户从 `/rooms` 的 Book 入口创建独立草稿。
2. 用户只可重新手动上传照片，不能从已有 Room 选择。
3. 系统从 EXIF 提取拍摄时间；用户仍只选择照片与风格，不填写章节或参与编排。
4. 后续生成、编辑与阅读流程与 Room zine 共用。

独立 zine 不应伪装成 Room。它需要用户所有权、自己的媒体上传 RPC、读取策略和删除策略。

## 5. 推荐领域模型（概念稿）

以下只是边界设计，不是最终数据库字段：

- **Zine**：作品身份、所有者/协作者、来源类型、关联 Room、标题、当前状态、当前版本、可见性。
- **Zine source**：选中的来源照片、来源评论、行程和用户补充说明。
- **Zine asset**：独立入口上传的媒体，或对 Room asset 的受控引用。
- **Zine generation job**：排队、处理中、成功、失败、取消；幂等键、模型、prompt 版本、token、成本、错误与重试。
- **Zine version**：一次不可变的布局快照。编辑或重排创建新版本，避免覆盖已发布结果。
- **Zine layout document**：封面、章节、页面、模板 id、slot、照片 id、裁切焦点、文字块和 design token 的结构化 JSON。
- **Template manifest**：模板版本、允许的页面原语、字体、颜色、密度、约束和兼容的 reader/page ratio。

推荐采用“来源引用 + 发布快照”的组合：草稿阶段可以读取最新素材；每次生成/发布版本固定当时的标题、评论摘录、照片关联和布局。已确认的 zine 保留生成时的媒体派生副本与评论快照，不因 Room 归档数据的后续清理而改变；账号删除和法定隐私删除仍必须拥有更高优先级的独立规则。

## 6. AI 排版管线

AI 的介入不是“一句话生成一本书”，而是一条有明确责任边界的策展与排版管线：

```text
来源快照
  → 照片视觉理解与 AI 精选（可选）
  → 时间 / 行程章节骨架
  → 封面与叙事节奏规划
  → 从模板语法中选择 spread
  → 确定性校验与 HTML/CSS 渲染
  → 低分辨率 contact sheet 视觉复核
  → 最多一次自动修复
  → Host 预览与确认
```

AI 拥有的是“在约束内做审美决定”的权力；系统拥有数据归属、页数、文字容量、照片完整性、折缝安全和渲染结果的最终裁决权。

### 6.1 输入预处理

- 只在服务器端读取私有素材，不从浏览器直连模型供应商。
- 为 AI 生成最大约 512px 的短期派生图；默认不发送原图。
- 输入每张图的稳定 photo id、宽高比、拍摄时间、可用评论、所属行程和 Host 选择顺序。
- 进行坏图检测、近似重复分组、方向归一化和基础清晰度分析。
- 不把长期签名 URL 写入 prompt、日志或数据库。

拍摄时间成为正式照片元数据。优先从 EXIF 读取，并允许独立 Book 上传时由用户修正。没有拍摄时间时保留明确的 `unknown`，不伪造时间。

行程匹配先由确定性算法完成：照片的 `captured_at` 落入 itinerary 的 `starts_at` 至实际/计划结束时间区间时归入该行程。若一张照片命中多个重叠行程、没有时间或没有命中，再交给 AI 根据画面与上下文建议归属。

“行程是否足够清晰”不交给模型随意决定，首版建议用可测规则：至少存在 2 个有效行程段，且至少 60% 的最终照片能唯一命中行程区间，才使用行程章节；否则直接切换到时间章节。该阈值要用真实 Room 样本校准。

时间章节先按当地日期边界与明显时间间隔形成候选组，再由 AI 合并过小章节并命名。若全部照片缺失时间，则 AI 才按人物、地点、色彩和事件语义形成主题章节。

### 6.2 第一次介入：照片理解与 AI 精选

对每张照片，模型只产生可验证的策展特征：

- 主体类别、人物/场景、情绪与事件提示。
- 画面方向、视觉重心、可裁切区域和需要保护的脸/主体。
- 清晰度、曝光和封面适配度。
- 与其他照片的近似重复或连续动作关系。
- 评论价值：是否存在适合成为短摘录的评论。

若 Host 选择“AI 精选”，模型依据以下目标给出集合，而不是只挑技术上最清晰的照片：

- 覆盖不同时间段和主要行程。
- 保留关键人物、地点和事件的多样性。
- 避免近似重复，但允许有叙事意义的连续镜头。
- 同时包含 hero、环境建立镜头和细节镜头。
- 优先保留拥有高价值评论的照片，但不因此牺牲整本视觉节奏。

### 6.3 第二次介入：封面与章节叙事

模型在时间/行程骨架上完成：

- 选择封面主图和 1–2 张备选图。
- 评估封面照片是否有足够标题留白、主体辨识度和缩略图辨识度。
- 确定章节顺序、章节标题和章节之间的节奏变化。
- 为每章指定开场 hero、过渡照片、细节照片与收尾照片。
- 从每张照片的评论中选择短摘录；不改写原评论正文。

封面不是普通第一页。每种风格拥有独立封面模板族，至少包括“留白框景封面”和“照片主导封面”。封面使用真实照片，不在 MVP 生成新图。封面标题来源仍待确认：默认建议使用 Room 名称，副标题使用日期范围或地点，避免 AI 发明与 Room 无关的标题。

### 6.4 第三次介入：布局规划

模型收到选定风格的 template manifest，只能从允许的 spread 原语中选择。它决定：

- 每个 spread 使用哪个布局原语。
- 每张照片进入哪个 slot。
- 每个 slot 的离散尺寸级别、裁切焦点与留白方向。
- 评论摘录出现在哪个允许的文字位置。
- 何时使用单图停顿、双图对话、三图节奏、联系表或章节扉页。
- 如何避免连续多个 spread 使用同一种构图。

模型不决定任意像素坐标，不返回 CSS，不旋转照片，不让图片互相遮挡，也不能创建模板 manifest 之外的结构。所谓“非整齐”来自不等比例的模块、错落的视觉重量与跨 spread 节奏，而不是失去网格。

### 6.5 模型输出契约

模型返回严格结构化布局文档，主要包含：

- `cover`：封面模板、主图、备选图、标题层级和焦点。
- `chapters`：来源类型、时间范围、标题、照片集合与顺序。
- `spreads`：模板 id、slot 与 photo id 映射、焦点、摘录 id。
- `backCover`：封底模板、日期/成员数量等允许的元数据。
- `rationale`：只用于审计的简短选择理由，不参与渲染。

返回值中只能引用当前来源快照中的稳定 id，不接受 AI 重写评论或凭空构造照片说明。

### 6.6 确定性校验与渲染

- 手动选图或 AI 精选后的最终照片必须全部使用；除封面主图可在内页再出现一次外，其他照片不得重复。
- 引用的 photo/comment/itinerary id 必须属于当前 zine 来源。
- 限制页数、单页照片数、文字长度、颜色 token、字号和裁切参数。
- 保证封面、封底、奇偶页、spread 和章节起始位置合法。
- 保护人脸和主要主体不落入中缝或危险裁切区。
- 统计连续布局重复、全书视觉密度和每章首尾节奏。
- 校验失败时先做确定性修复；无法修复才触发一次受限模型重试。
- HTML/CSS renderer 使用同一个 layout document 服务 StPageFlip、普通分页 fallback 和未来导出。

### 6.7 第四次介入：渲染后视觉复核

鉴于本功能的核心价值就是排版质量，MVP 建议包含一次受限视觉复核：把渲染后的封面与整书低分辨率 contact sheet 交给视觉模型，检查节奏重复、视觉失衡、裁切失误、封面辨识度和风格一致性。文字溢出仍由 DOM 测量处理，不交给视觉模型猜测。

复核只允许返回“通过”或有限修复指令，例如更换一个 spread 原语、交换同章两张照片、调整一个离散焦点。最多自动修复一次，禁止形成不受控的模型循环。预计额外增加约 $0.02–$0.10 / 本，但更符合“高度可用而非大量模板”的目标。

Host 点击“AI 重排”时，从章节叙事或布局规划阶段重新生成一个新版本；不得静默覆盖已经确认的版本。

## 7. 模板系统

每个风格不是一份硬编码页面，而是一个带版本的 manifest：

- 书页比例与安全边距。
- 字体与字号阶梯。
- 纸张、背景、正文与强调色 token。
- 封面布局集合。
- 章节扉页集合。
- 单页和双页 composition 集合。
- 允许的照片数量、方向和文字容量。
- 裁切、留白、边框、阴影、页码和装饰规则。
- 暗色阅读环境下的外层 reader 规则；书页本身是否保持纸张颜色待设计确认。

首发确认只做 2 套，并把精力投入可用性、素材适应性与整书节奏。两套都采用白色或轻微暖白书页、真实照片比例和隐藏网格，不采用自由旋转、照片遮挡、撕纸、胶带或手写贴纸等难以稳定生成的拼贴语法。

### 7.1 风格 A：Quiet Field / 留白画册（暂名）

定位：安静、克制、像摄影展览目录或高完成度旅行画册。适合风景、建筑、空间、静物和画面质量较统一的 Room。

视觉来源与原则：参考 Cereal 一类极简旅行编辑设计的留白、克制字体与照片尺度对比，同时采用摄影书中“把两页看作同一画布”“通过留白避开中缝主体”的做法。

可编码规则：

- 书页：纯白或极轻暖白；不使用有色大底。
- 隐藏网格：每页 6 列，spread 共 12 列；所有图片边缘必须落在网格线或半格线上。
- 密度：通常每个 spread 1–3 张照片，最多 4 张；至少约三分之一 spread 保持单图或大面积留白。
- 尺寸：只允许 `small / medium / large / hero` 四个离散级别。
- 构图：不对称但稳定，主要靠一大一小、偏置留白、跨页视觉对话和章节间尺度突变。
- 文字：最多两套字体；章节标题、短摘录和页码。评论摘录不覆盖照片。
- 满版：仅用于章节关键 hero，并必须通过主体/中缝安全检查；普通页优先保留白边。
- 节奏：大图后安排留白或小图，避免连续三次相同密度。

建议的 MVP spread 原语（10 个）：

1. 单页偏置 hero + 对页留白/短摘录。
2. 双页一大一小对话。
3. 横图跨两页但避开主体中缝。
4. 单页居中小图 + 对页大图。
5. 同比例双图镜像但尺寸不等。
6. 竖图 + 两张环境细节。
7. 三图阶梯，但共享两条对齐轴。
8. 章节扉页 + 小型建立镜头。
9. 纯摘录停顿页 + 对页照片。
10. 章节收尾小图 + 日期/地点。

封面模板：

- **A1 留白框景**：白底，小到中型 hero photo 偏置放置；Room 名称与日期位于独立网格区。
- **A2 安静满幅**：高封面适配度照片接近满幅，但保留一条明确白边或标题带；标题不压住人脸与视觉主体。

### 7.2 风格 B：Living Sequence / 旅行编年（暂名）

定位：更有人味、更像独立纪实 zine 或旅行日志；仍然干净，但节奏更密、图片组合更活。适合人物、聚会、移动过程、食物和大量手机随拍。

视觉来源与原则：借鉴 Apartamento 一类生活化编辑的松弛感，以及摄影 zine 中混合有边/近满幅照片、把 spread 当作整体、用连续镜头建立节奏的方法。它不是剪贴簿，而是“有编辑意识的非正式记录”。

可编码规则：

- 书页：白色，允许极少量黑色或单一品牌强调色用于章节编号和元数据。
- 隐藏网格：每页 4 列主网格 + 可选 8 列细分；只允许 3 种错位量，避免任意坐标。
- 密度：通常每个 spread 2–4 张照片，特殊联系表最多 5 张；每章至少保留一个单图停顿 spread。
- 尺寸：`detail / supporting / lead / hero` 四级；同一 spread 至少有一个明确 lead，不能所有照片等大。
- 构图：允许边缘贴页、局部裁切、横竖图混排和时间序列，但不允许旋转、重叠或装饰性相框。
- 文字：短评论像编辑旁注，固定在 3 个文本锚点之一；可显示作者名，但不覆盖照片。
- 节奏：用“建立场景 → 人物/动作 → 细节 → 评论停顿”组织行程，而不是平均分照片。
- 低质量但叙事重要的照片优先进入小型 supporting slot，不强行放大。

建议的 MVP spread 原语（10 个）：

1. 行程标题 + 一张建立场景图 + 时间元数据。
2. 一张 lead + 两张连续细节。
3. 横向动作序列三联。
4. 大型人物图 + 小型反应镜头。
5. 四图非等比联系表。
6. 两张近满幅照片形成对话。
7. 竖图靠外侧 + 内侧两张小图，保护中缝。
8. 评论摘录作为节奏停顿 + 一张小图。
9. 单图 hero 章节高潮。
10. 章节收尾联系图 + 下一段时间提示。

封面模板：

- **B1 纪实主图**：一张强叙事照片占据主要面积，Room 名称采用清晰编辑字体；日期作为小型档案信息。
- **B2 三图序列**：同一事件或同一时间段的三张照片组成非等宽序列；标题位于稳定白色区域。仅当三张图在色彩和语义上足够一致时使用。

### 7.3 两种风格共享的禁止项

- 不允许 AI 发明新的页面结构。
- 不允许单页超过模板定义的最大照片数。
- 不允许照片任意角度旋转、相互遮挡或跨出书页。
- 不允许文字覆盖人脸、主体或不可预测的照片区域。
- 不允许为了“填满”而拉伸、改变照片比例或重复普通照片。
- 不允许连续三个 spread 使用同一原语。
- 不允许把封面当作内页模板复用。

### 7.4 研究依据与下一步视觉验证

研究中反复出现的有效原则是：动态感来自页面之间的尺度变化、留白和视觉重量，而不是抛弃网格；将双页视作一个画布可以形成更自然的摄影叙事；封面应使用强代表性图片和极少文字。参考：

- [7 Layout Ideas for Your Photo Zine](https://lovetheindies.com/p/7-layout-ideas-for-your-photo-zine)
- [Portfolio Magazine：用序列、对比、留白和尺度变化建立编辑节奏](https://www.ikonographia.com/portfolio-magazine-brodovitch-reinvention-editorial-design/)
- [Cereal Volume 5 的留白与多图编辑示例](https://stylejuicer.com/design-illustration/design-cereal-magazine-volume-5/)
- [Apartamento 官方刊物页面](https://www.apartamentomagazine.com/)
- [Photo zine cover：强主图、极简字体与短文字](https://photographyicon.com/photography-zine-guide/)

这些名称和参数仍是设计假设，不是最终视觉稿。进入开发前应先用同一组 20–25 张真实 Room 照片，为两套风格各人工制作 4–6 个代表性 spread 和 2 个封面，作为排版引擎与 AI 输出的金标准。没有这组人工基线，不应仅凭 prompt 判断 AI 排版是否成功。

## 8. 权限、隐私与安全

- Room zine 只有 Host 可以创建、换风格、重排、改选评论、确认和删除；Room 成员私有只读。公开分享不在 MVP。
- 生成前说明照片和评论会被发送给所选 AI 服务处理，并记录用户同意版本。
- 只发送用户选择的照片及必要文字，不默认发送整个 Room 的聊天或成员资料。
- 作者显示名、头像和评论时间是否进入 zine 必须让产品明确；默认建议只用显示名与评论摘录，不发送头像给模型。
- 模型 API key 只存在服务端。
- AI 输入缩略图设置短保留期；prompt 和错误日志不得保存图片正文、签名 URL 或完整私密评论。
- 生成任务需要成员资格/所有权复核、Room 生命周期复核、限流、幂等和配额校验。
- 模型输出视为不可信输入，必须经过 schema 与资源归属校验。
- 需要定义 Room 成员退出、账号删除、照片删除、Room 删除对 zine 快照和分享链接的影响。
- 若素材可能包含未成年人或敏感场景，需要额外的使用提示、删除机制和供应商数据控制审查。

## 9. StPageFlip 阅读器边界

- 仅客户端动态加载。
- 固定页面比例，容器尺寸变化由 adapter 处理。
- 封面和封底使用 hard page；内页使用 soft page。
- 移动端 portrait 默认单页，满足宽度后使用 spread；具体断点由视觉测试决定。
- 书页只读，交互控件位于书本外层。
- 支持键盘/按钮翻页；触摸手势不得阻断页面外垂直滚动。
- 监听 init、flip、orientation、state；阅读进度是 UI 偏好，不写回 zine 布局版本。
- 组件卸载、切换版本和重新生成后必须销毁旧实例，避免重复 DOM 与事件。
- `prefers-reduced-motion` 下提供弱化动画或普通分页 fallback。
- 首版必须有无 StPageFlip 的静态页面 fallback，避免第三方库故障导致内容完全不可读。

## 10. 接入阶段与验收门

### Phase 0 — 产品决策与样本基线

交付：关闭第 12 节的开发前阻断项；确定两个入口的线框、权限、命名、首发风格和 10–20 组代表性素材样本。

验收门：产品规则没有会改变数据所有权、来源语义或版本语义的未决问题。

### Phase 1 — 版式语法与无 AI renderer

交付：zine layout schema、模板 manifest、两套风格设计稿、每套封面模板族、确定性分页/校验规则、普通静态 reader。

验收门：给定同一 layout document，所有设备输出稳定；长标题、极端宽高比、空评论和 25 张照片均不溢出。

### Phase 2 — 数据模型与生成任务基础

交付：zine/source/version/job/asset 边界、RLS、幂等、删除语义、用量台账、独立入口上传链路。

验收门：Room zine 与独立 zine 的读取和写入权限通过数据库测试；失败任务可安全重试且不重复扣额度。

### Phase 3 — 两个入口与手动草稿

交付：Room 照片选择、评论素材选择、行程/时间模式、独立上传、标题和风格选择、草稿保存。

验收门：不调用 AI 也能用确定性策略生成一本可读 zine，作为故障回退与质量基线。

### Phase 4 — AI 艺术指导

交付：多模态请求、严格 JSON 输出、验证/修复、任务状态、预算、重排额度、模型和 prompt 版本记录。

验收门：代表性样本的人工盲评显著优于确定性基线；无照片遗漏/越权引用；单本成本和 P95 延迟满足预算。

### Phase 5 — StPageFlip 接入

交付：客户端 adapter、封面/单页/spread、resize、进度、销毁、reduced-motion 和 fallback。

验收门：iOS Safari、Android Chrome、桌面 Chrome/Edge 的翻页、旋转、后台恢复和重复打开稳定；无 DOM 泄漏或页面重复。

### Phase 6 — 编辑、发布与灰度

交付：换风格、AI 整本重排、改选原评论摘录、版本保存、确认与回滚、埋点、成本告警和灰度开关。不提供页面、章节或照片位置编辑器。

验收门：小流量用户完成创建—生成—修改—阅读的端到端流程；生成失败可以恢复，素材删除行为符合规则。

### Phase 7 — 后续能力（不属于 MVP 默认范围）

- 页面级重排与局部重生成。
- PDF、印刷和高分辨率导出。
- 公开分享链接或协作编辑。
- AI 生成封面插画。
- 从 Chat 文本/图片导入。

## 11. 质量、成本与监控指标

- 创建漏斗：进入、选图完成、生成成功、保存、再次阅读。
- 生成成功率、校验修复率、重试率、取消率。
- 首稿接受率、换风格率、完整重排率、人工修改次数。
- 每本输入/输出 token、美元成本、AI 缩略图流量、队列等待和总耗时。
- 每个模板的使用率、溢出率、失败率和用户保留率。
- Reader 初始化失败、翻页错误、resize 重建次数、内存和长任务。
- 隐私与权限拒绝事件不得包含照片、评论正文或签名 URL。

建议在正式 AI 接入前建立离线评测集，覆盖：

- 1、2、3、10、25 张照片。
- 全横图、全竖图、混合比例、低光、截图、重复照片。
- 无行程、多行程重叠、照片没有拍摄时间。
- 无评论、超长评论、多语言、emoji、敏感内容。
- 中文、英文及混合标题。
- 每一套模板和移动/桌面尺寸。

## 12. 产品决策状态

### 12.1 已确认

- [x] 用户只选择照片与风格，不参与页面排版。
- [x] Room 中一房一本共享 zine，由 Host 创建和控制。
- [x] 只在 Room 结束后创建；生成时照片、评论与行程已冻结。
- [x] Room 选图有“Host 手动”和“AI 精选”两种方式。
- [x] 章节优先按真实拍摄时间匹配行程；行程不清晰时按时间组织。
- [x] 没有时间或无法匹配行程的照片交给 AI 做语义归属。
- [x] 评论由 AI 选择短摘录。
- [x] Host 可为照片改选评论摘录。
- [x] `/rooms` 使用现有 Create 菜单 Book 项；独立 Book 只允许重新上传照片。
- [x] Host 只可换风格、请求 AI 整本重排、改选照片对应的精选评论；不开放排版编辑。
- [x] zine 保留生成时的照片与评论快照；Room 结束后原评论不能修改。
- [x] 首版只做私有在线阅读。
- [x] 首发只做两套高度可用风格。
- [x] 封面属于正式生成结果，必须有独立模板与校验。

### 12.2 仍需确认的少量问题

- [ ] **AI 精选确认方式**：AI 给出照片集合后，Host 是否仍可增删再确认？本计划建议可以，因为照片选择是 Host 明确保留的权利。
- [ ] **评论“改选”语义**：建议只能换成同一照片下的另一条原始评论，不允许修改评论原文；是否确认？
- [ ] **封面文字**：默认使用 Room 名称 + 日期范围/地点，还是允许 AI 另外创作 zine 标题与章节标题？
- [ ] **封面选择**：Host 只选风格、由 AI 自动定封面，还是允许 Host 在 AI 提供的 2–3 个封面候选中选一个？后者仍属于照片选择，不是排版编辑。
- [ ] **容量**：Room 当前最多 25 张照片。AI 精选最多选多少、独立 Book 最多上传多少、最终最多多少页？建议首版均以 25 张、约 16–32 个内页为设计边界。
- [ ] **重排额度**：每本可请求多少次 AI 重排？成本计划暂按首稿 + 2 次重排。
- [ ] **独立 Book 权限**：默认仅创建者本人可见和控制，是否确认？
- [ ] **评论署名**：摘录是否显示作者显示名？是否显示时间？建议显示名字、隐藏头像、时间按风格可选但不发送头像给模型。
- [ ] **长期删除**：虽然发布后保留快照，但账号删除、隐私删除请求或整个 Room 永久删除时是否仍保留，需要另立合规规则。

## 13. 已收敛的 MVP 基线

- 一房一本，Room 结束后由 Host 创建。
- Host 选择照片和两套风格之一；其余策展、章节、封面与布局由 AI 完成。
- 手动选图与 AI 精选是两个入口；最终确认集合内的照片全部使用。
- 章节先用拍摄时间匹配清晰行程，否则按时间；缺失信息才交给 AI 语义分组。
- AI 从照片原评论中选短摘录，Host 可改选；原评论不因 zine 被改写。
- 封面使用真实照片和独立模板，不生成新图片。
- Host 只可换风格、AI 整本重排和改选评论，不可移动或缩放页面元素。
- zine 是生成时的不可变来源快照；每次重排形成新版本。
- Room zine 对 Room 成员私有；独立 Book 暂按创建者私有设计。
- 首版只做 StPageFlip 在线阅读与静态 fallback，不做公开链接、PDF 或印刷。
- 两套风格暂定为 Quiet Field / 留白画册和 Living Sequence / 旅行编年。
- AI 不输出页面代码；只输出受 schema、模板 manifest 与预算约束的布局计划。
- MVP 包含一次渲染后低分辨率视觉复核和最多一次自动修复。
