> 状态：已进入分批开发；第一、二批已提交，第三批数据基础与 27 张真实照片 proof 已在 `feature/zine-data-foundation` 实现，Phase 2 继续推进
> 建立日期：2026-08-02  
> 最近更新：2026-08-03  
> 当前版本：v0.8
> 维护方式：本文件是持续更新的产品、设计、数据与技术决策基线。实现严格按已确认批次推进，新增或改变产品边界前先更新本文件。

## 1. 目标与当前共识

Book 功能用于把照片、照片下的评论以及可选行程信息整理为可翻阅的数字 zine。系统应协助用户形成封面、章节与有审美的版式，但最终阅读与渲染必须稳定、可重复、可重新生成。

已经提出两个入口：

1. **Room 内入口**：一房一本共享 zine。Room 结束后由 Host 创建；Host 选择风格，并通过“手动选图”或“AI 精选”决定参与排版的照片。系统带入这些照片下的评论与房间行程。
2. **Rooms 页 Book 入口**：使用现有 Create 菜单中的 Book 项创建独立 zine；它不依赖任何 Room，只允许用户重新手动上传照片。

用户不参与页面排版。生成后只开放三类控制：更换风格、请求 AI 整本重排、处理某张照片对应的文字。文字处理包括接受 AI 精选评论、不使用评论，或由 Host 另写一段对照片的思考感悟。自由拖拽、任意布局、逐页微调不属于产品方向。

首版作品仅私有在线阅读，不提供公开分享、PDF 或印刷。

阅读器指定采用 [Nodlik/StPageFlip](https://github.com/Nodlik/StPageFlip)，并需要多套视觉风格。

当前暂定产品语言：

- `Book`：产品入口或功能名称。
- `Zine`：一本实际生成、编辑和阅读的作品。
- 最终对外是否统一为 Book、Zine 或其他名称，仍待确认。

## 2. 初步结论

### 2.1 AI 辅助排版可行，但不应让 AI 直接生成 HTML/CSS

推荐采用“**AI 艺术指导 + 参数化模板渲染**”的混合模式：

- AI 负责看图、理解评论与行程、选封面、编章节、选择版式、决定照片组合、裁切焦点和文字层级。
- 服务器只接受符合预定义 JSON Schema 的布局计划。
- 前端用经过设计与测试的 HTML/CSS 版式原语渲染页面。
- StPageFlip 只负责翻页和阅读交互，不拥有业务数据，也不决定版式。

不建议首版让模型输出任意 HTML、CSS 或整页位图，原因是：

- 结果不可控，文字溢出、照片遮挡、移动端错位很难彻底验证。
- 很难保持同一风格在不同作品和重新打开后完全一致。
- 任意代码或样式输出增加安全风险。
- 位图页不利于清晰文字、无障碍、响应式阅读与后续 PDF/印刷。
- 每次微调都要重新生成，成本与等待时间都会放大。

模板也不应只是少量固定“照片格子”。更合适的是建立一套参数化版式语法：单图满版、跨页主视觉、双图对话、三图节奏、留白引语页、章节扉页、时间轴页等。AI 在受控语法内组合，并可调整有限参数，例如焦点、留白方向、字号级别、图文比例和色彩 token。这能在审美变化与工程稳定之间取得平衡。

### 2.2 多模态成本不是首要风险，反复生成和工程复杂度才是

当前后端仍限制每个房间最多 25 张照片，zine 参与排版照片的硬上限已经确认采用 **48 张**。这意味着 Room 媒体上限不能继续等同于 zine 上限：Room 应允许积累多于 48 张来源照片，Host 再从中选择最多 48 张；独立 Book 则最多上传/纳入 48 张。页数由照片、章节和版式动态推导，AI 重排由速率与预算保护。按 OpenAI 官方视觉计费规则，`gpt-5.4-mini` 的图片输入以 32×32 patch 计费并乘以 1.62；其公开价格为输入 $0.75 / 1M tokens、输出 $4.50 / 1M tokens。以下 25 张场景仍保留为单位成本基线，接入时必须重新读取实时价格。

假设一次生成输入 25 张照片，模型只输出结构化布局 JSON：

| 方案 | 图片处理假设 | 估算输入 | 估算单次总模型成本 | 适用范围 |
| --- | --- | ---: | ---: | --- |
| 低成本首稿 | 每张缩放为 512×512，low detail | 约 10.4K 图片 tokens | 约 **$0.03 / 本** | 章节、封面候选、布局选择 |
| 高细节首稿 | 每张按高细节上限估算 | 约 62.2K 图片 tokens | 约 **$0.07 / 本** | 需要更精确裁切与细节判断 |
| 生成 + 2 次重排示例 | 同一作品发生三次完整调用 | 上述约 3 倍 | 约 **$0.09–$0.21 / 本** | 用于理解重排的线性成本，不代表产品次数上限 |
| 渲染后视觉复核 | 额外把页面缩略图交给模型审稿 | 视页数和循环次数 | 通常再增加 **$0.02–$0.10 / 轮** | 后续高质量或付费模式 |

48 张上限场景的图片输入约是 25 张基线的 1.92 倍；若其他文本与输出长度相近，首次多模态调用应暂按约 **$0.05–$0.14 / 本**做工程预算，而不是承诺价格。加上一次 contact sheet 复核、失败重试和重排后，建议 MVP 先以 **$0.10–$0.35 / 个生成版本**作为保守监控带，再用真实样本校准。48 张不应在一个高细节请求里无差别处理，仍执行缩略图首筛、章节级分批和少量高细节升级。

估算未包含税费、供应商价格变化、网络流量、队列计算、页面截图、Storage 和监控成本。文本评论和行程通常只占很小一部分输入成本。若不用图像生成模型创造新封面插画，则不存在高额图片输出费用。

建议首版成本策略：

- 普通生成使用 512px 派生缩略图和低成本视觉模型。
- 只有封面候选或模型判断不确定的照片才升级到高细节。
- 生成前先做确定性去重、尺寸检查和元数据整理。
- 产品不限制重排次数；每次重排前显示生成状态，并由账户预算、速率限制和异常滥用保护控制资源。
- 记录每个生成任务的模型、prompt 版本、输入/输出 token、估算美元成本、延迟和失败原因。
- 设置单任务硬预算与全局月度预算，超限时回退到确定性排版。
- 规模预算可暂按每 10,000 本约 $300–$700 的“一次首稿”模型成本估算；真实值必须用试运行样本校准。

即使设置照片上限，也不应假设所有照片永远适合一次模型请求。超过单批预算时采用分层管线：

1. 按批次理解照片、去重并产生紧凑视觉特征。
2. 按时间/行程形成章节后，在章节内做精选、评论和局部排版。
3. 全书模型只读取章节摘要、封面候选和 spread 摘要，负责全局节奏。
4. 视觉复核使用分页 contact sheet，而不是一张无限长图片。

后台仍需要文件大小、并发、账户 Storage、单次模型预算和异常滥用安全阈值。成本大致随照片数和生成版本数线性增长，必须在生成前展示预计耗时与资源消耗。

- [OpenAI Images and vision：图片细节、缩放与 token 计算](https://developers.openai.com/api/docs/guides/images-vision)
- [OpenAI GPT-5.4 mini 发布与价格](https://openai.com/index/introducing-gpt-5-4-mini-and-nano/)
- [OpenAI 模型目录](https://developers.openai.com/api/docs/models)

### 2.3 StPageFlip 可以采用，但需要隔离适配层

StPageFlip 适合当前需求：MIT 许可、无运行时依赖、支持 HTML 页面、封面硬页、portrait/landscape、移动端和更新页面。`page-flip` 当前 npm 版本为 2.0.7。

需要接受以下风险：

- npm 包约五年没有发布新版本，维护活跃度低。
- 项目当前是 Next.js 16.2.10 + React 19.2.4，不能默认认为旧 React wrapper 与当前生命周期完全兼容。
- portrait 模式会 clone HTML 页面；书页内部不应放表单、重复 id 或复杂交互。
- resize、React 重渲染、快速切换作品和销毁重建需要专项验证。

因此计划直接在客户端适配核心 `page-flip`，不把 `react-pageflip` wrapper 作为默认依赖。适配层负责动态加载、初始化、`updateFromHtml`、当前页同步、resize 重建和 `destroy()`。书页保持只读；上一页、下一页、目录、模式切换等操作放在被 clone 的页面 DOM 之外。

阅读器必须是可替换的表现层。即使 StPageFlip 出现兼容问题，zine 的布局文档仍可被普通分页阅读器或未来 PDF renderer 使用。

参考：

- [StPageFlip README 与 API](https://github.com/Nodlik/StPageFlip)
- [page-flip npm 版本记录](https://www.npmjs.com/package/page-flip?activeTab=versions)

## 3. 当前仓库审计

### 3.1 已具备的基础

- Next.js 16.2.10、React 19.2.4、Supabase。
- 房间照片已进入 `public.photos`，照片评论已进入 `public.photo_comments`。
- 房间行程已进入 `public.itineraries`。
- 私有媒体使用 `room-media` bucket、RLS 和签名 URL。
- 图片已有 display、thumbnail、placeholder、尺寸和 revision 等派生信息。
- Room 页面已有 Photos、评论详情、Itinerary 和成员权限基础。
- `/rooms` 已有一个被禁用的 Book 菜单项，可作为入口位置候选，但是否等同于需求中的“右上角 Book 按钮”需要确认。

### 3.2 必须补齐的数据能力

1. **没有正式 zine 数据模型**：当前没有 zine、版本、章节、页面、布局、来源照片或生成任务表。
2. **没有拍摄时间**：`photos.created_at` 是上传时间，不是照片拍摄时间；当前图片压缩链路也没有持久化 EXIF 时间。若“按时间”是按真实拍摄时间编章，需要新增 `captured_at`、时区和缺失值策略。
3. **评论没有内容类型**：生产 `photo_comments` 只有正文与作者，无法区分正式 caption、精选引语和普通讨论。mock 层虽有 `caption` 兼容字段，但不能当作生产契约。
4. **全局手动 Book 没有上传边界**：现有上传 RPC 要求用户是某个 active room 的成员，不能直接用于独立 zine。
5. **48 张 zine 上限尚未贯通**：数据库上传 RPC 当前限制 Room 为 25 张。需要把“Room 来源照片容量”和“单本 zine 最多参与 48 张”拆成两个约束；同步提高 Room 媒体容量，并为独立 Book 建立最多 48 张的分批上传、Storage 配额与大作品生成策略。
6. **没有异步生成任务与用量台账**：需要状态机、幂等、重试、预算、超时和生成版本记录。
7. **没有快照语义**：照片、评论或行程在 zine 生成后发生修改或删除时，当前没有规则决定已生成作品如何变化。

### 3.3 历史实现的处理原则

仓库文档记录 2026-07-23 曾存在 Memoir/Book、双页、纸张样式和 `page-flip` 原型，但该实现已在 2026-07-26 后撤回，相关运行时代码和依赖当前都不存在。

本次原则：

- 不恢复旧 reducer 命令或旧 `boardItems` / `boardComments` 兼容模型。
- 可复用历史验证结论，例如客户端动态加载、阅读器生命周期分离、偶数页和封面尺寸稳定。
- 新功能直接基于生产 `photos`、`photo_comments`、`itineraries`、`assets` 和新的 zine 领域模型设计。

## 4. 推荐产品流程

### 4.1 Room 内入口

确认后的流程：

1. Room 结束，照片、评论与行程进入不可继续编辑的归档状态。
2. Host 在 Room 内点击 Book。
3. Host 选择选图方式：
   - **手动选图**：Host 直接勾选照片。
   - **AI 精选**：AI 按画面质量、时间覆盖、人物/场景多样性、评论价值与重复度给出不超过 48 张的建议集合；Host 可以增删并最终确认。
4. Host 选择两套风格中的一套。
5. 系统展示选中照片、AI 将使用的评论范围、预计页数与生成额度。
6. 后台冻结来源快照，按拍摄时间匹配行程并建立章节候选。
7. AI 完成封面、章节、评论摘录和整本布局，系统执行确定性校验与一次受限视觉复核。
8. Host 预览成品，只能：
   - 更换整本风格；
   - 请求 AI 整本重排；
   - 接受或隐藏某张照片的 AI 精选评论；
   - 为某张照片另写一段 Host 自己的思考感悟，替代精选评论进入 zine。
9. Host 确认当前版本，一房一本的共享 zine 对 Room 成员私有可见。

手动选中的照片默认全部进入成品。AI 精选模式选择出的最终集合也全部进入成品。封面主图可以在内页再出现一次，其他照片默认不重复。

### 4.2 Rooms 页独立入口

确认后的流程：

1. 用户从 `/rooms` 的 Book 入口创建独立草稿。
2. 用户只可重新手动上传照片，不能从已有 Room 选择。
3. 系统从 EXIF 提取拍摄时间；用户仍只选择照片与风格，不填写章节或参与编排。
4. 后续生成、编辑与阅读流程与 Room zine 共用。

独立 zine 不应伪装成 Room。它需要用户所有权、自己的媒体上传 RPC、读取策略和删除策略。

## 5. 推荐领域模型（概念稿）

以下只是边界设计，不是最终数据库字段：

- **Zine**：作品身份、所有者/协作者、来源类型、关联 Room、标题、当前状态、当前版本、可见性。
- **Zine source**：选中的来源照片、来源评论、行程和用户补充说明。
- **Zine asset**：独立入口上传的媒体，或对 Room asset 的受控引用。
- **Zine note**：Host 为某张照片新增的 zine 专属感悟。它与原始 `photo_comments` 分离，拥有自己的作者、正文与版本关联，不修改或冒充 Room 评论。
- **Zine generation job**：排队、处理中、成功、失败、取消；幂等键、模型、prompt 版本、token、成本、错误与重试。
- **Zine version**：一次不可变的布局快照。编辑或重排创建新版本，避免覆盖已发布结果。
- **Zine layout document**：封面、章节、页面、模板 id、slot、照片 id、裁切焦点、文字块和 design token 的结构化 JSON。
- **Template manifest**：模板版本、允许的页面原语、字体、颜色、密度、约束和兼容的 reader/page ratio。

推荐采用“来源引用 + 发布快照”的组合：草稿阶段可以读取最新素材；每次生成/发布版本固定当时的标题、评论摘录、照片关联和布局。已确认的 zine 保留生成时的媒体派生副本与评论快照，不因 Room 归档数据的后续清理而改变；账号删除和法定隐私删除仍必须拥有更高优先级的独立规则。

## 6. AI 排版管线

AI 的介入不是“一句话生成一本书”，而是一条有明确责任边界的策展与排版管线：

```text
来源快照
  → 照片视觉理解与 AI 精选（可选）
  → 时间 / 行程章节骨架
  → 封面与叙事节奏规划
  → 从模板语法中选择 spread
  → 确定性校验与 HTML/CSS 渲染
  → 低分辨率 contact sheet 视觉复核
  → 最多一次自动修复
  → Host 预览与确认
```

AI 拥有的是“在约束内做审美决定”的权力；系统拥有数据归属、页数、文字容量、照片完整性、折缝安全和渲染结果的最终裁决权。

### 6.1 输入预处理

- 只在服务器端读取私有素材，不从浏览器直连模型供应商。
- 为 AI 生成最大约 512px 的短期派生图；默认不发送原图。
- 输入每张图的稳定 photo id、宽高比、拍摄时间、可用评论、所属行程和 Host 选择顺序。
- 进行坏图检测、近似重复分组、方向归一化和基础清晰度分析。
- 不把长期签名 URL 写入 prompt、日志或数据库。

拍摄时间成为正式照片元数据。优先从 EXIF 读取，并允许独立 Book 上传时由用户修正。没有拍摄时间时保留明确的 `unknown`，不伪造时间。

行程匹配先由确定性算法完成：照片的 `captured_at` 落入 itinerary 的 `starts_at` 至实际/计划结束时间区间时归入该行程。若一张照片命中多个重叠行程、没有时间或没有命中，再交给 AI 根据画面与上下文建议归属。

“行程是否足够清晰”不交给模型随意决定，首版建议用可测规则：至少存在 2 个有效行程段，且至少 60% 的最终照片能唯一命中行程区间，才使用行程章节；否则直接切换到时间章节。该阈值要用真实 Room 样本校准。

时间章节先按当地日期边界与明显时间间隔形成候选组，再由 AI 合并过小章节并命名。若全部照片缺失时间，则 AI 才按人物、地点、色彩和事件语义形成主题章节。

### 6.2 第一次介入：照片理解与 AI 精选

对每张照片，模型只产生可验证的策展特征：

- 主体类别、人物/场景、情绪与事件提示。
- 画面方向、视觉重心、可裁切区域和需要保护的脸/主体。
- 清晰度、曝光和封面适配度。
- 与其他照片的近似重复或连续动作关系。
- 评论价值：是否存在适合成为短摘录的评论。

若 Host 选择“AI 精选”，模型依据以下目标给出集合，而不是只挑技术上最清晰的照片：

- 覆盖不同时间段和主要行程。
- 保留关键人物、地点和事件的多样性。
- 避免近似重复，但允许有叙事意义的连续镜头。
- 同时包含 hero、环境建立镜头和细节镜头。
- 优先保留拥有高价值评论的照片，但不因此牺牲整本视觉节奏。

### 6.3 第二次介入：封面与章节叙事

模型在时间/行程骨架上完成：

- 选择封面主图和 1–2 张备选图。
- 评估封面照片是否有足够标题留白、主体辨识度和缩略图辨识度。
- 确定章节顺序、章节标题和章节之间的节奏变化。
- 为每章指定开场 hero、过渡照片、细节照片与收尾照片。
- 从每张照片的评论中选择短摘录；不改写原评论正文。

Host 可以不采用 AI 精选评论，并为照片写入新的 zine note。AI 在后续重排中必须把这段 Host 感悟视为高优先级已确认内容，但仍由排版引擎决定它出现在哪个合法外角注释位置。

封面不是普通第一页。每种风格拥有独立封面模板族，且 AI 只能使用最终参与排版的照片生成 2–3 个完整封面候选。封面默认无文字；若版式需要识别信息，只允许把 Room 名称或日期作为很小的元素放在外角，不能让文字成为封面主体，也不由 AI 创作新的大标题。封面使用真实照片，不在 MVP 生成新图。

### 6.4 第三次介入：布局规划

模型收到选定风格的 template manifest，只能从允许的 spread 原语中选择。它决定：

- 每个 spread 使用哪个布局原语。
- 每张照片进入哪个 slot。
- 每个 slot 的离散尺寸级别、裁切焦点与留白方向。
- 评论摘录出现在哪个允许的文字位置。
- 何时使用单图停顿、双图对话、三图节奏、联系表或章节扉页。
- 如何避免连续多个 spread 使用同一种构图。

模型不决定任意像素坐标，不返回 CSS，不旋转照片，不让图片互相遮挡，也不能创建模板 manifest 之外的结构。所谓“非整齐”来自不等比例的模块、错落的视觉重量与跨 spread 节奏，而不是失去网格。

### 6.5 模型输出契约

模型返回严格结构化布局文档，主要包含：

- `cover`：封面模板、主图、备选图、无字/微型角标模式和焦点。
- `chapters`：来源类型、时间范围、标题、照片集合与顺序。
- `spreads`：模板 id、slot 与 photo id 映射、焦点、摘录 id。
- `backCover`：封底模板、日期/成员数量等允许的元数据。
- `rationale`：只用于审计的简短选择理由，不参与渲染。

返回值中只能引用当前来源快照中的稳定 id，不接受 AI 重写评论或凭空构造照片说明。Host 新写的感悟以独立 zine note id 进入布局文档。

### 6.6 确定性校验与渲染

- 手动选图或 AI 精选后的最终照片必须全部使用；除封面主图可在内页再出现一次外，其他照片不得重复。
- 引用的 photo/comment/itinerary id 必须属于当前 zine 来源。
- 限制页数、单页照片数、文字长度、颜色 token、字号和裁切参数。
- 保证封面、封底、奇偶页、spread 和章节起始位置合法。
- 保护人脸和主要主体不落入中缝或危险裁切区。
- 统计连续布局重复、全书视觉密度和每章首尾节奏。
- 校验失败时先做确定性修复；无法修复才触发一次受限模型重试。
- HTML/CSS renderer 使用同一个 layout document 服务 StPageFlip、普通分页 fallback 和未来导出。

### 6.7 第四次介入：渲染后视觉复核

鉴于本功能的核心价值就是排版质量，MVP 建议包含一次受限视觉复核：把渲染后的封面与整书低分辨率 contact sheet 交给视觉模型，检查节奏重复、视觉失衡、裁切失误、封面辨识度和风格一致性。文字溢出仍由 DOM 测量处理，不交给视觉模型猜测。

复核只允许返回“通过”或有限修复指令，例如更换一个 spread 原语、交换同章两张照片、调整一个离散焦点。最多自动修复一次，禁止形成不受控的模型循环。预计额外增加约 $0.02–$0.10 / 本，但更符合“高度可用而非大量模板”的目标。

Host 点击“AI 重排”时，从章节叙事或布局规划阶段重新生成一个新版本；不得静默覆盖已经确认的版本。

## 7. 模板系统

每个风格不是一份硬编码页面，而是一个带版本的 manifest：

- 书页比例与安全边距。
- 字体与字号阶梯。
- 纸张、背景、正文与强调色 token。
- 封面布局集合。
- 章节扉页集合。
- 单页和双页 composition 集合。
- 允许的照片数量、方向和文字容量。
- 裁切、留白、边框、阴影、页码和装饰规则。
- 暗色阅读环境下的外层 reader 规则；书页本身是否保持纸张颜色待设计确认。

首发确认只做 2 套，并把精力投入可用性、素材适应性与整书节奏。两套都采用白色或轻微暖白书页、真实照片比例和隐藏网格，不采用自由旋转、照片遮挡、撕纸、胶带或手写贴纸等难以稳定生成的拼贴语法。

### 7.1 风格 A：Quiet Field / 留白画册（暂名）

定位：安静、克制、像摄影展览目录或高完成度旅行画册。适合风景、建筑、空间、静物和画面质量较统一的 Room。

视觉来源与原则：参考 Cereal 一类极简旅行编辑设计的留白、克制字体与照片尺度对比，同时采用摄影书中“把两页看作同一画布”“通过留白避开中缝主体”的做法。

可编码规则：

- 书页：纯白或极轻暖白；不使用有色大底。
- 隐藏网格：使用稳定列线、基线与安全边距建立秩序，但不要求所有 spread 复用同一组可见构图。
- 密度：以单图、双图和少量多图形成呼吸变化；照片数由素材与章节节奏决定，不以网页参考中的七种排版或一张固定模板清单为上限。
- 尺寸：照片保留原比例，尺寸来自连续但受安全边界限制的网格跨度，而不是只套 `small / medium / large` 卡片。
- 构图：不对称但稳定，主要靠一大一小、偏置留白、跨页视觉对话、尺度突变和照片间的方向关系。
- 文字：最多两套字体；评论或 Host 感悟直接依附于所属照片的外角区域，不覆盖照片、不漂移到无关页面。
- 满版：仅用于章节关键 hero，并必须通过主体/中缝安全检查；普通页优先保留白边。
- 节奏：大图后安排留白或小图，避免连续三次相同密度。

Quiet Field 不以有限“成品模板列表”运行，而使用可组合的版式语法：

- **画布层**：单页或整个 spread；决定中缝、外侧和安全区。
- **视觉主次层**：无主图、单主图或一主多辅；保证每个 spread 有明确视觉入口。
- **网格跨度层**：照片可以占不同列数与高度，但边缘必须与合法网格锚点建立关系。
- **配对层**：AI 根据人物朝向、运动方向、色彩、光线或语义选择呼应/对比关系。
- **留白层**：留白被声明为上、下、内侧、外侧或整页停顿，不是排完照片后剩余的空位。
- **注释层**：每张有文字的照片生成一个与其绑定的外角注释锚点。
- **节奏层**：控制相邻 spread 的密度、尺度与重复度，不允许整本变成同一种网格。

这套语法可以生成大量组合，但仍有明确边界：AI 不能任意坐标放置、旋转或遮挡照片。我们约束的是“克制、呼吸、照片本身和秩序”，不是约束为七种或十种页面成品。

外角注释规则：

- 左页照片优先使用远离中缝的左外角，右页照片优先使用右外角；根据留白可选择上角或下角。
- 注释与照片保持固定视觉间距，并至少与照片的一条边对齐。
- 一张照片最多一个注释块；不是每张照片都必须有文字。
- AI 精选评论保持原文摘录并显示原评论者名字；Host 新写感悟只显示正文，不显示名字。
- 面向英文用户时，AI 评论摘录与 Host 感悟分别执行英文 word limit；当前建议评论摘录最多 28 words、Host 感悟最多 40 words，具体数值待确认。
- 文字超出该照片合法外角容量时，优先缩短 AI 摘录或换锚点，不缩小到不可读，也不把文字压到照片上。
- 注释跟随照片参与重排，不允许在重排后指向错误照片。

封面模板：

- **A1 无字留白框景**：白底，小到中型 hero photo 偏置放置；完全依靠照片尺度和位置建立识别。
- **A2 无字安静满幅**：高封面适配度照片接近满幅，但保留一条明确白边。
- **A3 微型角标**：仅在需要作品识别时，把 Room 名称或日期以很小字号放在外角，不与照片争夺视觉中心。

### 7.2 风格 B：Living Sequence / 旅行编年（暂名）

定位：更有人味、更像独立纪实 zine 或旅行日志；仍然干净，但节奏更密、图片组合更活。适合人物、聚会、移动过程、食物和大量手机随拍。

视觉来源与原则：借鉴 Apartamento 一类生活化编辑的松弛感，以及摄影 zine 中混合有边/近满幅照片、把 spread 当作整体、用连续镜头建立节奏的方法。它不是剪贴簿，而是“有编辑意识的非正式记录”。

可编码规则：

- 书页：白色，允许极少量黑色或单一品牌强调色用于章节编号和元数据。
- 隐藏网格：每页 4 列主网格 + 可选 8 列细分；只允许 3 种错位量，避免任意坐标。
- 密度：通常每个 spread 2–4 张照片，特殊联系表最多 5 张；每章至少保留一个单图停顿 spread。
- 尺寸：`detail / supporting / lead / hero` 四级；同一 spread 至少有一个明确 lead，不能所有照片等大。
- 构图：允许边缘贴页、局部裁切、横竖图混排和时间序列，但不允许旋转、重叠或装饰性相框。
- 文字：短评论像编辑旁注，固定在 3 个文本锚点之一；可显示作者名，但不覆盖照片。
- 节奏：用“建立场景 → 人物/动作 → 细节 → 评论停顿”组织行程，而不是平均分照片。
- 低质量但叙事重要的照片优先进入小型 supporting slot，不强行放大。

Living Sequence 的首批 composition family 示例（不是最终数量上限）：

1. 行程标题 + 一张建立场景图 + 时间元数据。
2. 一张 lead + 两张连续细节。
3. 横向动作序列三联。
4. 大型人物图 + 小型反应镜头。
5. 四图非等比联系表。
6. 两张近满幅照片形成对话。
7. 竖图靠外侧 + 内侧两张小图，保护中缝。
8. 评论摘录作为节奏停顿 + 一张小图。
9. 单图 hero 章节高潮。
10. 章节收尾联系图 + 下一段时间提示。

封面模板：

- **B1 无字纪实主图**：一张强叙事照片占据主要面积，不使用标题干扰画面。
- **B2 三图序列**：同一事件或同一时间段的三张参与排版照片组成非等宽序列。仅当三张图在色彩和语义上足够一致时使用。
- **B3 微型档案角标**：只在外角以很小的 Room 名称或日期提供识别。

### 7.3 两种风格共享的禁止项

- 不允许 AI 发明新的页面结构。
- 不允许单页超过模板定义的最大照片数。
- 不允许照片任意角度旋转、相互遮挡或跨出书页。
- 不允许文字覆盖人脸、主体或不可预测的照片区域。
- 不允许为了“填满”而拉伸、改变照片比例或重复普通照片。
- 不允许连续三个 spread 使用同一原语。
- 不允许把封面当作内页模板复用。

### 7.4 Quiet Field 的扩展参考谱系

不把任何一本书直接复制成模板，而是从成熟摄影书中抽取可进入引擎的原则：

| 参考 | 值得提取的原则 | 在引擎中的表达 |
| --- | --- | --- |
| Masao Yamamoto，《Small Things in Silence》 | 小幅照片与巨大白页形成亲密感；相邻图片可以尺寸完全不同，但气氛连续 | AI 可主动缩小重要照片，不把“重要”等同于“铺满”；用白页和比例差建立停顿 |
| Rinko Kawauchi，《Illuminance》 | 图片配对依靠光线、色彩、形状和情绪呼应，不只依靠拍摄时间 | 在同一章节内，AI 可用视觉相似度调整相邻顺序，但不能跨越确定的时间/行程事实 |
| Aperture 2025 PhotoBook Awards 中 András Ladocsi 的作品 | 宽松的一图一 spread 与有意识的序列让构图本身被看见 | 当照片内部构图足够强时选择单图停顿，不为提高密度强塞其他照片 |
| Jeano Edwards，《EverWonderful》 | 满幅、较小图片和不等比例配对交替，形成松弛但经过编辑的节奏 | 节奏层交替 lead、supporting 与停顿页；非正式感来自序列，不来自装饰 |

| Alexey Brodovitch 的《Portfolio》 | 摄影、文字、尺度、留白与中断被视作一个连续系统 | 评价对象是整本 contact sheet 的节奏，不是逐页是否各自漂亮 |

### 7.5 下一步视觉验证

这些名称和参数仍是设计假设，不是最终视觉稿。进入开发前应先用同一组代表性真实或授权 Room 照片，为两套风格各人工制作至少 6 个 spread 和 3 个封面候选，覆盖单图、双图、多图、横竖混合、评论外角注释和无评论状态，作为排版引擎与 AI 输出的金标准。

金标准还必须增加一本达到最终照片上限的压力册，验证章节级分批排版后的全书节奏。没有人工基线，不应仅凭 prompt 判断 AI 排版是否成功。

## 8. 前端体验与信息架构

### 8.1 体验定位：Book Studio，不是排版工具

整个创建区域暂称 **Book Studio**。它应让用户感到自己正在选择、审阅和确认一本 zine，而不是填写后台表单；同时不能使用会暗示自由排版的画布、拖拽手柄、图层面板、裁切框或格式工具栏。

视觉上分为两层：

- **应用外壳**继续使用现有品牌 token：暖灰 `canvas`、纸白 `surface`、深色 `ink`、低饱和 `muted/line`，不建立第三套主色。
- **zine 校样**始终使用模板规定的纸白页、真实页比与清晰书脊。即使用户处于 dark mode，变暗的也只是工作台背景，纸页本身保持模板颜色，避免错误预览成品。
- Bodoni Moda 用于步骤标题、风格名称和少量章节预览；Geist 用于操作与正文；Geist Mono 用于页码、照片序号、日期与生成状态。
- 页面、照片和校样框尽量保持直角、细线与真实比例；避免把每一步做成圆角 SaaS 卡片墙。控件位于纸页外，不污染成品预览。
- 动效来自翻页、纸张叠层和校样切换，使用短距离 transform/opacity；创建流程不滥用 StPageFlip，正式阅读阶段才使用真实翻页。

Book Studio 应使用独立全屏路由，而不是长流程 modal。建议概念路由为：

- Room Host：`/rooms/[roomId]/book`，Room 成员进入同一地址时只看到当前确认版本的 Reader。
- 独立 Book：`/books/new` 创建，`/books/[bookId]` 继续草稿或阅读。

具体 URL 可在代码审计后调整；需要保留草稿恢复、浏览器返回和生成任务后台继续执行的能力。

### 8.2 总流程

```text
入口 / 草稿恢复
  → 01 Select：手动选片或 AI 精选，Host 最终确认 ≤ 48
  → 02 Style：用真实入选照片预览并选择两种风格之一
  → 03 Words：逐张决定采用原评论、写 Host 感悟或无文字
  → Compose：冻结来源快照并生成章节、封面与整本布局
  → Cover：从 2–3 个完整封面候选中选择
  → Reader：确认、阅读；Host 可进入有限 Revision
```

顶部只保留返回、作品状态和轻量步骤标记，例如 `01 / 03`；底部使用一个明确的主动作。草稿自动保存，不设置频繁的显式 Save 按钮。步骤数量显示的是生成前的三个决策阶段，Cover 属于生成结果的校样确认，不伪装成生成前可预知的普通表单步骤。

### 8.3 Select：照片选择

进入后先出现一张极简编辑扉页，提供两个平等入口：

- **Select myself**：从 Room 的全部来源照片中手动选择；独立 Book 则先上传，再进入相同选择界面。
- **Let AI curate**：AI 先给出建议集合，Host 仍在同一界面增删并确认。AI 精选不是自动发布，也不改变照片顺序。

选择界面采用按拍摄时间稳定排列的 **contact sheet / proof sheet**，不做营销式图库卡片：

- 缩略图尽量保留原始宽高比，用 justified rows 或受控自然比例网格提高密度；不以统一正方形裁切隐藏构图。
- 选中状态使用照片外的细墨线、外角 folio 编号和 `18 / 48 selected`，不在照片中心覆盖巨大彩色勾选。
- 桌面端可在 contact sheet 旁显示固定的选择摘要；移动端使用底部粘性计数与 Continue，满 48 张后仍允许取消已有选择，但不能继续新增。
- 点击选择与查看原图必须可区分且均有无障碍标签；键盘、触屏和读屏不能只依赖颜色表达选中状态。
- 查看照片时复用现有沉浸式 Photo Detail 的基本心智，但归档 Room 中只读原评论；Book 的选择开关和后续 zine note 属于独立控件。
- AI 精选完成后显示 `Curated 32 from 146`，Host 可以直接调整。首版不在 146 张照片上逐一堆叠“为什么入选/未入选”的解释；只提供一个简短的整体策展说明，例如时间覆盖、重复去除和人物/场景平衡。
- 用户不拖拽排序。最终顺序仍由拍摄时间、行程章节和 AI 叙事规划决定。

独立 Book 的上传与选择共用同一 contact sheet，但必须显示上传、派生图生成和失败重试状态。原文件未处理完成前可以取消，不应把无法解码的照片带入下一步。

### 8.4 Style：风格选择

风格不能只用一张抽象封面或文字说明来选。系统应使用当前入选照片即时生成低成本、确定性的 **真实素材样张**：每种风格至少展示封面、图像主导 spread、带外角评论 spread 三种代表状态。

- 移动端两个风格作为横向 snap 的小型书册校样；桌面端并列比较，但一次只强调一个当前候选。
- 风格名称、短句说明和适配倾向位于纸页之外；纸页内只出现将来真正可能生成的内容。
- 选择风格不调用完整 AI 排版。预览先由固定 seed 与模板 renderer 生成，避免用户每次横滑都产生模型成本和等待。
- 切换风格时保持同一组照片，帮助用户比较“编辑语言”而不是比较素材。
- 点击 **Use Quiet Field** 或 **Use Living Sequence** 后进入文字审阅，仍可返回修改，不立即消耗一次完整生成。

### 8.5 Words：照片评论与感悟

这个阶段在英文界面中建议命名为 **Words** 或 **Photo notes**，不叫 `Edit comments`，因为 Room 原评论始终不可修改。

界面采用“照片校样 + 外部编辑抽屉”：

- 校样区把当前照片放入所选风格的纸白页，并在真实合法外角位置预览文字；控制区永远位于纸页外。
- 顶部 filmstrip/序号用于在最多 48 张入选照片间快速切换；提供 `All / With comment / Reflection / No text` 筛选，并显示尚未处理数量。
- 对拥有评论的照片，AI 先展示一个只读原文摘录、评论者显示名和 `Use this comment` 选择。用户可以展开查看该照片的其他原评论作为上下文，但 MVP 不提供在所有评论间手工制作摘录的复杂编辑器。
- Host 可以改为 **Write a reflection**，输入独立 zine note，并显示英文 word counter；该文字在成品中不署名。
- 第三个明确状态是 **No text**。每张照片只能采用“原评论摘录 / Host 感悟 / 无文字”之一，避免同一外角堆叠两套身份不清的文字。
- 若 Host 在原评论与感悟之间切换，未提交的感悟草稿暂时保留，直到离开作品或明确清空，防止误触丢字。
- AI 重排可以移动照片和它绑定的外角注释，但不会改写 Host 感悟，也不会把文字绑定到另一张照片。

“编辑照片”在当前产品边界内建议只表示：查看大图、加入/移出本书，以及在生成后重新选择照片并创建新版本。MVP 不开放滤镜、旋转、手动裁切、缩放焦点或逐页换位；否则用户事实上已经开始参与排版，并会破坏 AI 的裁切与中缝安全契约。这个含义需要产品最终确认。

### 8.6 Compose、封面与生成状态

生成前显示一张类似 colophon 的审阅页，而不是技术配置表：入选照片数量、风格、采用原评论数量、Host 感悟数量、章节依据以及私有可见范围。主动作使用 **Compose book**。

- 点击后冻结该次来源快照并创建异步 generation job；离开页面不取消任务。
- 等待画面可使用纸张逐步成册的安静动效，但只展示真实任务阶段：Preparing photographs、Building chapters、Composing pages、Reviewing book。
- 首稿完成前不暴露半本可翻的书。失败时保留当前草稿与上一可读版本，并提供 Retry。
- 首稿完成后先进入 **Cover proof**：并列/横滑展示 2–3 本完整封面校样，只能来自已入选照片；Host 选择一个候选，再进入全书 Reader。
- 如果某个候选包含微型角标，必须可在校样中按实际大小判断；无字候选优先排在第一位。

### 8.7 Reader 与有限 Revision

Reader 的可见 UI 严格只有两个元素：

1. **Background**：使用当前最终封面上的照片作为全屏背景来源，执行覆盖式放大、强模糊与轻微明暗压制。它只提供色彩和氛围，不能辨认出清晰内容，也不承担任何文字或交互。
2. **Reader**：唯一清晰前景。未打开时，以单本闭合 zine 的完整外接尺寸在视口水平和垂直居中；打开为双页时，以整个 spread 的完整外接尺寸重新居中。不能只让书脊或某一页居中，也不能因为从封面进入双页而永久向一侧偏移。

不显示标题、页码、上一页/下一页、Single/Spread、退出、Host 工具栏或悬浮按钮。翻页依靠拖拽/滑动、页面左右点击区和键盘方向键；退出依靠浏览器/应用返回与 `Escape`。仍需在 DOM 中保留对读屏可理解的语义翻页入口和焦点顺序，但它们不是常驻视觉元素。

封面背景的来源规则：单图封面直接使用该照片；多图封面由 cover layout document 明确一个 `backgroundSourcePhotoId`，通常选择封面主图。背景使用 display derivative 或专用低分辨率派生图，不解码原图；加载前先显示同图 placeholder，避免出现第三种 loading 画面。背景层 `aria-hidden`，避免读屏重复朗读同一张照片。

Host 的修改入口不放在 Reader 内。Host 先通过浏览器/应用返回离开纯阅读场景，再从 Book Studio 的作品页进入 Revision：

- Change style
- Recompose with AI
- Photo notes
- Choose another cover
- Change photographs

任何会改变内容或布局的操作都生成新 `zine version`。当前已确认版本在新版本生成完成前继续可读，绝不让 Room 成员看到处理中或半完成状态。普通 Room 成员没有 Revision 控件；独立 Book 只有创建者可见。

### 8.8 响应式、状态与无障碍验收

移动端是主设计面，不是桌面工作台的压缩版：

- 选择照片为单列/双列自然比例 contact sheet，主动作固定在安全区上方；不使用横向双栏编辑。
- Style 与 Cover 使用可见下一项边缘的横向 snap，明确还有候选可浏览。
- Words 每次专注一张照片；filmstrip、文字选择和键盘弹出后仍需保留 Save/Next 可达性。
- Reader 在窄屏使用单页，仍保持整页居中；满足阅读尺寸后才打开为居中的双页，不强制把双页缩小到不可读。

必须设计并测试以下状态：Room 尚未结束、没有照片、来源照片少于成册基线、AI 精选排队/失败、已达 48 张、上传部分失败、没有任何评论、英文文字超限、生成排队/超时/重试、旧版本可读、新版本处理中、StPageFlip 初始化失败和 reduced motion。

Phase 0 视觉交付不只画 happy path。两套风格应各提供 Select、Style、Words、Cover、Reader 的移动端主状态，以及至少一个 48 张桌面 contact sheet 和一个生成失败恢复状态。

## 9. 权限、隐私与安全

- Room zine 只有 Host 可以创建、换风格、重排、接受/隐藏精选评论、写入新感悟、确认和删除；Room 成员私有只读。公开分享不在 MVP。
- 生成前说明照片和评论会被发送给所选 AI 服务处理，并记录用户同意版本。
- 只发送用户选择的照片及必要文字，不默认发送整个 Room 的聊天或成员资料。
- 作者显示名、头像和评论时间是否进入 zine 必须让产品明确；默认建议只用显示名与评论摘录，不发送头像给模型。
- 模型 API key 只存在服务端。
- AI 输入缩略图设置短保留期；prompt 和错误日志不得保存图片正文、签名 URL 或完整私密评论。
- 生成任务需要成员资格/所有权复核、Room 生命周期复核、限流、幂等和配额校验。
- 模型输出视为不可信输入，必须经过 schema 与资源归属校验。
- 需要定义 Room 成员退出、账号删除、照片删除、Room 删除对 zine 快照和分享链接的影响。
- 若素材可能包含未成年人或敏感场景，需要额外的使用提示、删除机制和供应商数据控制审查。

## 10. StPageFlip 阅读器边界

- 仅客户端动态加载。
- Reader stage 占据完整视口；固定页面比例，容器尺寸变化由 adapter 处理。
- 封面和封底使用 hard page；内页使用 soft page。
- 移动端 portrait 默认单页，满足宽度后使用 spread；具体断点由视觉测试决定。
- 可见结构只允许模糊封面背景层与 Reader 层。背景层覆盖视口、不可交互、`aria-hidden`；Reader 之外不渲染常驻可见控件。
- 闭合态按单本 zine 的外接矩形居中；双页态按整个 spread 的外接矩形居中。adapter 不能依赖 StPageFlip 默认偏移，必须用实测书本尺寸校正水平与垂直中心，并验证打开/闭合转换没有跳边。
- 书页只读。支持拖拽/滑动、左右页面点击区与键盘方向键翻页；语义按钮可供读屏与键盘使用但默认视觉隐藏，获得焦点时仍需有可访问反馈。
- 退出使用浏览器/应用返回和 `Escape`，Host 的 Revision 入口位于 Reader 之外的 Book Studio。
- 监听 init、flip、orientation、state；阅读进度是 UI 偏好，不写回 zine 布局版本。
- 组件卸载、切换版本和重新生成后必须销毁旧实例，避免重复 DOM 与事件。
- 背景取最终封面主图的低分辨率派生图，并在 cover layout document 中保存来源照片 id；应用强模糊、轻微缩放和压暗/提亮规则，使任何封面照片都不会与纸页竞争。背景与书本必须共用同一封面版本，不能在换封面后残留旧图。
- 即使照片有上限，也不得一次解码整本原图。Reader 只预加载当前 spread 与相邻窗口，其余页面保留轻量 DOM/placeholder；达到照片上限的作品要专项验证 StPageFlip 的 HTML clone、总 DOM 数量和移动端内存。
- 若 StPageFlip 在最大作品页数下不能稳定工作，静态分页 fallback 必须继续可读。
- `prefers-reduced-motion` 下提供弱化动画或普通分页 fallback。
- 首版必须有无 StPageFlip 的静态页面 fallback，避免第三方库故障导致内容完全不可读。

## 14. 已收敛的 MVP 基线

- 一房一本，Room 结束后由 Host 创建。
- Host 选择照片和两套风格之一；其余策展、章节、封面与布局由 AI 完成。
- 手动选图与 AI 精选是两个入口；最终确认集合内的照片全部使用。
- 章节先用拍摄时间匹配清晰行程，否则按时间；缺失信息才交给 AI 语义分组。
- AI 从照片原评论中选短摘录；Host 可以接受、隐藏或另写一段 zine 专属感悟，原评论不被改写。
- 封面只能使用参与排版的真实照片。AI 生成 2–3 个候选供 Host 选择，不生成新图片；默认无文字或仅有微型外角文字。
- Host 只可换风格、AI 整本重排、重新选择照片和处理照片文字，不可移动或缩放页面元素。重新选片创建新版本，旧版本在生成期间继续可读。
- zine 是生成时的不可变来源快照；每次重排形成新版本。
- Room zine 对 Room 成员私有；独立 Book 仅创建者本人可见和控制。
- 首版只做 StPageFlip 在线阅读与静态 fallback，不做公开链接、PDF 或印刷。Reader 可见 UI 只有由最终封面主图生成的模糊全屏背景和居中的 zine；不显示任何常驻控件。
- 两套风格暂定为 Quiet Field / 留白画册和 Living Sequence / 旅行编年。
- Quiet Field 的评论和 Host 感悟依附在所属照片外角，不使用独立引语页作为默认方案。
- zine 最多使用 48 张照片。Room 可拥有更多来源照片供 Host 选择；达到上限的作品采用分批分析、章节汇总、预算和滥用保护。
- AI 可生成简短英文章节名。
- AI 评论摘录最多 28 个英文单词，Host 感悟最多 40 个英文单词；原评论显示评论者名字，Host 感悟不显示署名。
- 独立 Book 仅创建者本人可见和控制。
- AI 不输出页面代码；只输出受 schema、模板 manifest 与预算约束的布局计划。
- MVP 包含一次渲染后低分辨率视觉复核和最多一次自动修复。
