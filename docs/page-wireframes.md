# EventSpace 页面线框与信息层级 v1

> 文字线框用于确认页面骨架和内容顺序。它不表示最终像素视觉稿，也不包含功能代码。

## 1. 路由总览

| 区域 | 主要页面 | 目的 |
| --- | --- | --- |
| 公开 | 首页、邀请进入、认证、法律页 | 解释产品、创建/加入、登录。 |
| 用户首页 | 进行中、已归档、搜索/筛选、账户菜单 | 回到自己的活动空间。 |
| 创建 | 分步创建向导、成功/分享 | 快速建立私密临时房间。 |
| 独立实验 | `/zine` 创建器、手动排版、Reader | 在不改变 Room MVP 的前提下探索照片到 Zine 的创作流程。 |
| 房间 | Chat、Photos、Itinerary、成员、分享、管理面板 | 活动进行中的核心协作。 |
| 归档 | 回忆册入口、只读 Chat/Photos/Itinerary、个人移除确认 | 浏览自己的只读活动记忆。 |
| 状态 | 审核等待、冻结、处理归档、访问终止、断线 | 清晰说明当前可否操作。 |

## 2. 公开首页

### 移动端

```text
┌──────────────────────────────────┐
│ EventSpace                  Log in│
│                                  │
│   [抽象图钉照片 / UI 卡片背景]     │
│                                  │
│   Make the moment                │
│   live longer.                   │
│                                  │
│   [ Create a room              ] │
│   [ Join with a link           ] │
│                                  │
│   A private space for the moment.│
└──────────────────────────────────┘
│ Chat      Photos      Itinerary   │
│ 三张简短功能卡，随后是法律链接        │
└──────────────────────────────────┘
```

- 首屏占满首个视口；背景照片/模拟 UI 是抽象层，不承载任何可读信息。
- `Create a room` 是唯一强主按钮。`Join with a link` 为次按钮。
- 不展示公开房间、活动发现流、价格比较或冗长营销章节。

### 桌面端

- 保留同一阅读顺序，增加左右留白与背景卡片的空间层次。
- 文字列限制在舒适阅读宽度，避免标题横跨整屏。
- 功能卡在首屏之后以三列呈现。

## 3. 用户首页

### 默认：单张横滑房间流（移动端）

```text
┌──────────────────────────────────┐
│ EventSpace                    ◉   │
│ [ Search rooms...              ]  │
│                                  │
│ Active              Archived      │
│                                  │
│     ┌────────────────────────┐   │
│     │                        │   │
│     │  75% Photos 牌堆预览      │   │
│     │  （真实照片缩略图窗口）    │   │
│     │                        │   │
│     ├────────────────────────┤   │
│     │ Summer at the lake  ▯  │   │
│     │ • 3h 12m left · 6 people│  │
│     └────────────────────────┘   │
│              ●  ○  ○              │
│                                  │
│                         [ + Create]│
└──────────────────────────────────┘
```

- 横滑一次突出一张大卡；收藏书签浮于卡片右上角。
- 进行中状态及倒计时仅位于信息区，绝不压在照片牌堆上。
- 搜索与筛选展开后只改变结果集；仍以单张横滑为默认浏览方式。
- 用户可切换到双列纵向浏览，适合快速查找；该模式不取代默认阅读体验。
- 空状态只保留一句情绪化短句和创建按钮。

### 桌面端

- 活动卡按可用空间扩展为 2–3 列，但卡片仍保持“封面 + 信息区”的杂志比例。
- 搜索、筛选与视图切换占据标题行右侧，不形成数据后台式侧栏。

## 4. 创建房间向导

```text
┌──────────────────────────────────┐
│ ←  Create a room           3 / 3 │
│ ────────────────                   │
│                                  │
│ Review your room                 │
│                                  │
│ Room                             │
│ About                            │
│ Duration                         │
│ Capacity                         │
│                                  │
│ [ Create room                   ]│
└──────────────────────────────────┘
```

- 一步只完成一个决策；顶部提供返回、标题、低干扰进度 `n / 3` 与细线。
- 当前创建向导为 Details、Timing、Review 三步；不提供 Leadership / Access 独立步骤。
- Review 页以可编辑 row 汇总 Room、About、Duration、Capacity 和条款确认。
- 付费只在创建时可选，或配额超出时再出现；不在日常导航中常驻。

## 5. 邀请、身份与审核等待

### 邀请页

```text
┌──────────────────────────────────┐
│ EventSpace                 Log in │
│                                  │
│        [ avatar / initials ]      │
│          Summer at the lake       │
│          Ends 9:30 PM · 6 / 10    │
│                                  │
│ Nickname                          │
│ [ Avery                         ] │
│ [ Request to join              → ]│
└──────────────────────────────────┘
```

- 只展示名称、说明、结束时间、当前人数和人数上限。
- 不显示聊天、Photos、完整成员名单或其他私密内容。
- 已登录用户可带入账号昵称和头像；未登录访客提交时创建 anonymous session，头像使用昵称首字母。
- 当前加入页不采集申请备注；若恢复备注，需要重新补线框、RPC 和测试。

### 审核等待

- 保持邀请卡的房间信息；显示安静的等待反馈、头像脉冲和可退出入口。
- 页面每隔数秒轮询审核状态；通过后自动进入房间，被拒绝时显示拒绝状态和返回邀请入口。
- 不提前加载房间内容。

## 6. 房间共同外壳

```text
┌──────────────────────────────────┐
│ [Chat]        Summer at the lake  │
│                 • 3h 12m [Plan]  │
│                                  │
│      ← 横拖 / 吸附切换三页 →        │
│                                  │
│             当前页面内容           │
└──────────────────────────────────┘
```

- 顶部为单层悬浮胶囊：左、右两侧显示可跳转到相邻页面的动态图标；房间名、状态和倒计时按整个屏幕严格居中，点击中央区域打开 Room options。
- Chat / Photos / Itinerary 三页保持挂载在原生横向 scroll-snap 轨道；初始定位 Photos。非交互内容区域可横拖换页，页内内容独立纵向滚动，顶部按钮仍是稳定的切页入口。
- 最后 15 分钟提升细提示的视觉权重；最后一分钟轻微提示，绝不使用遮挡弹窗。
- 分享、成员与更多操作从中央 Room options 继续进入抽屉/底部面板，不把管理工具常驻在正文。
- 分享面板由 Host 打开时自动创建一组真实 private invite URL、短码和可扫描 QR；非 Host 只看到不可用状态。

## 8. Photos

```text
┌──────────────────────────────────┐
│ Photos                            │
│ ┌──────────────┬──────────────┐  │
│ │    photo     │    photo     │  │
│ │              │              │  │
│ └──────────────┴──────────────┘  │
│ ┌──────────────┬──────────────┐  │
│ │    photo     │    Add        │  │
│ └──────────────┴──────────────┘  │

```

- Photos 为紧凑照片网格，末项为上传入口；首次进入定位最新照片，但不改变其数据排序。
- 点击照片进入全视口详情，大图完整 `contain` 展示，作者、评论列表和安全区输入栏形成单一阅读层级；本人或管理员可删除。
- 当前不提供 Book、双页 spread、caption 层、相机入口、Chat 内容导入、纸张样式或复杂自由排版。

## 9. Itinerary

```text
┌──────────────────────────────────┐
│ Today                             │
│ ┌──────────────────────────────┐ │
│ │ 7:00–8:30 PM      IN PROGRESS│ │
│ │ Meet at Riverside             │ │
│ │ Riverside · Maya        ›     │ │
│ └──────────────────────────────┘ │
│                                  │
│ Tomorrow                          │
│ ┌──────────────────────────────┐ │
│ │ 10:00 AM · Brunch             │ │
│ │ Not started              ›     │ │
│ └──────────────────────────────┘ │
└──────────────────────────────────┘
```

- 按时间纵向排序，跨日用简洁日期文字分隔。
- 时间卡优先显示起止时间、标题、地点、负责人和自动推导的状态，不显示签到或参与人数。
- 地点仅用文字和 Google Maps / Apple Maps 外链图标；第一版不嵌入真实地图。
- 已结束、进行中、未开始分别使用低饱和红、绿、灰纯色卡片；亮色和深色模式均保持文字对比度。
- 每次进入默认定位到进行中的卡片；没有进行中项时定位到下一项，全部结束时定位到最后一项。
- 点击卡片展开说明、地图入口与有权限时的编辑操作；新增/编辑使用移动端底部编辑卡，不做签到表单。

## 2026-07-26 当前 Room 线框同步

- Chat 消息区采用全宽彩色圆角卡堆叠：左侧成员标识、右侧文字区内的姓名/时间/正文；本人卡右缩，成员标识置右。每张卡都展示元信息，不作连续消息隐藏。
- 底部输入区是浮于页面边缘的单一白色胶囊，左侧小圆形工具入口、中央文本、右侧黑色录音/发送主按钮；没有 Camera、相册或位置按钮。
- Photos 为多列照片网格，末项为添加照片卡；点击后进入全屏照片详情和评论，不存在双页 spread 或 Book 控件。
- `/rooms/new` 为 Details、Timing、Review 三步；不再有 Access 或 Leadership 独立步骤。
- 用户可单独选择自己列表中的卡片封面；删除只影响自己的列表。

### 被踢出/拉黑

- 仅显示无内容的访问终止页与必要说明；不泄露任何房间信息。

## 11. 抽屉、底部面板与提示

- 分享、成员、审批、评论和不可逆操作在移动端使用底部面板，桌面端可转为右侧抽屉。
- 高风险操作必须单独二次确认，并用明白语言说明后果。
- 普通错误、断线和重试只用短底部提示条与局部按钮，不以中心弹窗打断聊天。
- PWA 在首访以轻量提示出现；不干扰核心 CTA 与邀请进入流程。

## 12. Account

- 顶部使用严格居中的 `EventSpace` 品牌，左侧为无可见圆框的返回箭头，右侧留空；不显示营销式大标题或 `Local account` 状态文字。
- 页面采用移动端单列账户中心：身份卡、Account mode、三张主题预览、本地数据卡和法律链接依次排列，不使用“左侧介绍 + 右侧表单”的桌面结构。
- 身份卡展示头像图片或缩写、昵称、账户状态、邮箱与 Active / Memories / Photos 摘要；点击编辑图标后在卡片内部展开昵称编辑，已登录账号可同时上传头像。
- System / Light / Dark 使用带真实配色缩略的三列选择卡，窄屏保持稳定尺寸。
- Account mode 与 Reset local data 使用覆盖整个视口的底部操作卡；危险操作必须显示删除范围并二次确认。
- 页面卡片与覆盖层均适配亮暗主题、安全区和 `prefers-reduced-motion`。

## 2026-07-30 当前页面结构同步

- `/rooms/new` 完成页保留邀请卡，但 QR 已是真实 invite URL；origin 尚未可用时复制和 QR 应禁用或显示占位。
- `/rooms` 顶部账号入口渲染账号头像图片或 initials，不再只显示文字缩写。
- `/rooms` 卡片主视觉现在是 Photos 牌堆预览：数据可来自房间全部 ready photos，界面只限制同时显示/预渲染窗口；卡片横滑不应被描述为最多 5 张数据。
- `/rooms` Grid/Magazine 切换使用短暂淡出淡入并保留当前房间视觉锚点；这是布局过渡，不新增导航层级或服务端状态。
- Room sidebar、Chat 消息、Members 审核列表和 Itinerary 负责人均渲染同一 avatar 组件；签名 URL 不可用时回退 initials。
- Photos 上传、评论和删除会展示云端错误消息；失败后页面回到服务器快照，不保留未成功的乐观照片。
- Account、Rooms、Room New 和 Room detail 路由使用 loading skeleton 稳定首帧；skeleton 只表示加载中，不展示假数据或假可操作按钮。
- Room UI 基线已经因 avatar / QR / media error 变更重新锁定，详见 [`room-ui-baseline.md`](./room-ui-baseline.md)。

## 2026-07-19 历史同步：Chat 与旧 Board 结构

> 本节保留为旧 Board 实现记录；当前正式结构以本页“Photos”章节和 2026-07-27 Room 外壳同步为准。

### Chat

- 消息区按日期分隔，连续同作者消息形成视觉分组；自己的消息靠右。
- 底部输入条只有加号、自动增高文本区和发送/按住录音按钮；有文字时发送按钮替换录音按钮。
- 加号打开底部附件卡，以图标卡展示 Camera、Photos、Location、Poll、Votes、Search，并先收起键盘。
- 长按消息打开底部操作卡；图片预览、图片大图和 Votes 使用覆盖整个视口的 Portal。
- 离开最新位置时显示回到底部按钮和未读数；本人发送后自动回到最新，其他消息不强制抢滚动。

### Board

- Board 保持无边框全屏画布；右下角只保留 fit、背景、添加三键 Dock。
- 添加按钮打开 2 × 2 创建卡：Camera、Photos、Note、Doodle；背景按钮打开六个横向材质卡。
- Camera / Photos 选图后进入单层横滑相框工作台，当前居中卡即选中样式，确认后才 pin 到画板。
- Note Studio 从底部进入，横滑切换 paper / ink / sage，文字输入直接发生在卡片内部。
- Doodle Studio 覆盖包括房间标题和 tabs 在内的完整视口；纸张为主视觉，颜色与工具卡悬浮底部。
- 短点击照片打开覆盖完整视口的照片详情，大图在上，作者与纵向评论在下，评论输入固定在详情底部；不再在照片内部显示弹幕。
- Sequence 为单列纵向内容流，照片保持原始比例，并复用照片评论体验。

## 2026-08-11 当前同步：Zine 页面结构

`/zine` 是独立的全屏创建器，不嵌入 Room 外壳：

- 顶部：关闭入口、`Create zine` 标题和 `AI layout` 二态开关。
- 进度导航：Name、Photos、Style、Overview/Arrange、Reader；底部固定 Back / Continue 或 Open reader 操作。
- Name：标题输入和书脊预览。
- Photos：拖放/选择图片区、双行照片瀑布流、Add more、删除和 Photo Note 输入；照片卡的视觉分行不表达阅读顺序。
- Style：横向滚动的真实页面比例 Demo，当前 5 个样式。
- Overview：名称、照片数、Note 数、样式和照片摘要的可编辑总览。
- Arrange：全屏书页舞台；空白页上的 Add page、焦点模式工具、Photo library 和 Recipe library 抽屉。抽屉关闭后恢复书页舞台，不新增页面级导航。
- Reader：独立全屏阅读器、封面/双页/封底状态、前后 spread 控制和单页焦点镜头；关闭回到进入 Reader 前的 Overview 或 Arrange。

该路由当前只保存组件内存，刷新或离开页面即丢失；不应在 Room 线框、归档入口或正式产品导航中画成已发布 Zine。

## 2026-08-12 当前同步：Recipe Arrange 与 Preview Matrix

- Arrange 的 Recipe library 需要同时表达作用域（单页/跨页）、兼容性、Note 模式、容量和应用结果；Recipe 应用后若有照片未放置，必须在工作台显示明确状态，不能让用户误以为内容已排完。
- 单页 Recipe 的操作目标是当前聚焦页，配对页保持不变；跨页 Recipe 从任一侧进入都作为一次原子操作。照片焦点属于具体放置实例，拖动调整需要有可撤销的反馈。
- `/zine/preview-matrix` 是 development-only 的内部线框/验证入口，不属于用户导航；它以 Editor / Reader 两种模式并列检查 Reference Recipe、图片比例和 Note 超限，不替代正式 Reader 的翻页体验。
